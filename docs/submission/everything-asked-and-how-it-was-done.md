## 0. The product in four lines

desk. is a local desk for the person who pays for AI coding agents. It reads the logs the agents already write, ties every dollar to work that landed in git, explains why a limit was hit, checks daily whether the agent got worse against a control arm, drafts a spend policy and tries to break it, replays it on a month it never saw, and signs what it concludes so a stranger can verify it offline. Repository: https://github.com/Pratiikpy/agent-spend-desk. Video: https://youtu.be/3LaYZ0VCgXI. Hosted screens: https://desk-demo.vercel.app/. Primary track: Track 3, Reasoning Architecture. Full description: `docs/product-description.md`.

## 7. How it works behind the scenes, in the order a run happens

**1. The sample.** `desk sample build` generates a constructed team from a seed: 14 engineers, 987 sessions as real-format Claude Code logs, real git repositories, planted waste (loops, idle polling, cache misses, sub-agent fan-out) and a tool-version and model-mix change on 14 October. `truth.json` keeps what was planted so every finding can be scored against it.

**2. The ledger.** The reader takes Claude Code logs read-only (Codex and OpenCode too), de-duplicates by message and request id, handles sidechains and cache buckets, and stores token counts. A price book (a dated snapshot of first-party prices) turns counts into dollars later, so a price change can be applied again with the old cost kept. Every dollar carries a class. A hash chain over what happens to the ledger (`desk ledger verify`) lets a stranger see that no event was changed or removed.

**3. The limit autopsy.** The heaviest five-hour window is split into causes (loops, repeated reading, idle polling, sub-agent fan-out, cache misses, work that was needed), the fixes are ranked with intervals, and a block says what it could not know. Sessions are tied to commits with a confidence level; a dollar lands on the ladder kept, merged, committed, reverted or unlinked, and unlinked is "unknowable", not waste.

**4. Ask.** For a question such as "What changed before 2026-10-15?":
- The Risk Router and Scout Intent read the request first: is it a read of the ledger, or a request to change spend or policy phrased as a question? Instruction-like text is flagged and removed, never obeyed. The decision is stored with the question as a hash, not as text.
- The Planner (Nemotron, through a `plan_answer` tool whose argument is a typed program) returns steps such as spend, share, per-day, top sessions, landing, changes before. A plan critic (code) checks that the program has what the question needs (a share needs a numerator and a denominator) and sends it back once.
- Read-only specialists run each step against the ledger, the Zetaris facts and the Meterless engines. Code does every sum and percentage. Each step yields a claim with its rows and a query hash.
- The Explainer (Nemotron) writes the answer from the claims; it never sees the question, only what the program is about. The Auditor (code) rejects any sentence whose figure no claim supports; the Explainer may revise twice, then the sentence is dropped.
- The answer is stored with an id. `desk verify-answer <id>` runs the steps again later and says which sentences still hold. A separate check adds one known call to the ledger inside a rolled-back savepoint and requires the figures to move, which shows the answer comes from the ledger (`docs/verification/citation-faithfulness-2026-10-25.md`).
- If the model is unavailable or no recording exists, the rule planner and rule explainer answer and the trace says why. A real printed line from a sample run: `fallback: cassette_miss: E_CASSETTE_MISS: no recording for role ask_planner`. The answer still carries its rows.

**5. Propose.** The Drafter (Nemotron) drafts a spend policy from the training month's waste findings. Code checks that the draft only narrows the policy in force and, if not, returns a counterexample and the Drafter revises (in the recorded trace the first draft would have paused 81 of 311 landed sessions, the check caught it, and the second draft paused none). The Attacker looks for requests that step around the policy and the hardener closes what it finds. The policy is then replayed on a held-out month it was not drafted from. The headline is the landed work the policy would have blocked (5 of 333 on the sample), not the savings, which is shown beneath it as an upper bound.

**6. The canary.** A fixed pack of 52 small tasks runs daily on two arms, one of them a control, and a regression is called only against the control, with a paired statistic, a 99% interval and a computed smallest detectable change (about 21 points on the recorded design). A model switched on purpose on day 15 is found at -40.0 points while the control stays flat; none of 100 no-change histories was called a regression.

**7. Approval, the dossier and the verifier.** The owner approves a change by echoing the request id and the action digest. The conclusion becomes an Ed25519-signed in-toto statement in a DSSE envelope, with the rows its figures come from. `npm run desk-verify` recomputes it on plain Node with the network off; one changed byte makes it fail and name the row. A signature shows the record was not altered after signing and its figures follow from its rows; it does not show the agent logs were truthful.

**8. The gate.** Before an agent's tool call, a hook asks the gate; the gate reserves the worst-case cost, then settles after the call. It fails closed: a broken checker is a block, distinguishable from a refusal. Claude Code and Codex CLI were run for real against it (blocked with no gate, blocked by a refusing policy, allowed by a permitting one); Cursor and Gemini CLI have adapters that pass their contract tests and are advisory until run live. A tool with no hook can be governed by pointing its OpenAI-compatible base URL at the gateway door. `desk enforcement` says per tool what is enforced, advisory or notify only.

**9. Record and replay.** `--record` makes live calls to Nemotron or Zetaris and stores each reply keyed by role and request hash. `--sample` replays them with no key and no network, which is why a fresh clone reproduces the tables. Which model answered is on every reply and, through Nightshift, signed.

**10. What is measured about the product itself.** Link confidence is checked against planted truth (99.2% of high-confidence links right); the wind tunnel's "90%" range held 73% of 64 constructed months, and the screen says so; a preregistered head-to-head on one model gave one call 12, a tool-using agent 45 and the Desk 55 of 60 with seven written predictions held; the role-removal study and the model-mix test are in section 4. The scorecard (`desk scorecard --check`) recomputes the published page byte for byte.
