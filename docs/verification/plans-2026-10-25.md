# Plans: every window, the tool's figure beside the local count (2026-10-25)

`desk plans [--agent codex|claude_code] [--at TIME]` shows each plan window your tools report on, and the morning brief's Plan limits cards now carry the same two figures.

## What it shows

For each tool, the plan in use (the plan of the newest reading) and every window length that plan has, five-hour, weekly or a 30-day credit window, each labelled by its own length:

- **Official**: the tool's own reading: percent used, when the window resets, how old the reading is, and the outlook from how past windows of that plan ended (or why there is none).
- **Local**: a count of the tokens these logs hold for the tool's own provider's models in the window so far, and, when this plan's history teaches what a percent is worth, what that count would be as a percent with an interval. It is judged only against windows that have finished, so the window in question is never part of the estimate that judges it. When the two differ it says so and says why (the tool's figure includes other devices and uses that leave no trace here); neither figure is changed to fit the other. With too little history it gives the count and no percent.
- **Linear, no history**: with too few past windows for an outlook, the pace of the last hour carried straight forward, said to be exactly that: "at that pace it would reach 100% in N minutes, before or after the reset", never a probability.
- A tool with calls and no reading of its own (Claude Code, until its status line is turned on) is a local count over five hours, labelled as having no official figure, with the one command that gets one.
- **Events**, last fourteen days: a window reaching its limit (a reading at 99.5% or more, once per window), and a change of model in a thread, marked "within an hour of a limit hit (the logs do not say why)" when one is near. The `<synthetic>` placeholder the logs use for an error is not a model.

## What was run

- `tests/desk/plans.test.ts` (11): agreement and disagreement between the figures on a plan whose percent is worth exactly 10,000 tokens, only the tool's own provider's models counted, too little history giving a count and no percent, the straight-line pace (and none for a flat or stale reading), a tool with no reading, a tool the ledger has no session of, a limit hit listed once, a model change near and not near a hit, the placeholder left out, fourteen days and no further, the tool filter, a quiet fortnight.
- On this machine: the Codex ledger shows a free plan's weekly window (its last reading from a window that has reset) and its 30-day window (2% used, local count 66K tokens, no percent from only 3 windows that moved enough); the Claude Code ledger shows 206.9M tokens in the last five hours with no official figure, and nine real model changes in the last fortnight.

## Defects found by running it on real data

- The model changes included hundreds of switches to and from the `<synthetic>` placeholder, which is an error message, not a model: now left out.
- The first version fitted the percent's worth using the window being judged, which makes the check agree with itself: now only finished windows are used.

## Not covered

- No Claude Code plan reading has ever been captured here: the status line has not been turned on, and its fields are not verified against a real session. The Claude half of this view is the local count.
- A limit hit is read from the tool's own readings only. An API error that is a limit (the logs flag 653 error calls here) cannot be told from other errors, because the ledger keeps no message text; those are not counted as limit hits.
- A change of model is not shown to be caused by a plan; the view says only that it followed a limit hit.
- Monthly credits appear only as a window a tool reports (Codex's free plan reports a 30-day one); there is no separate credit balance.
- The outlook needs thirty past windows of the same plan and length; only the Codex plus five-hour window has that.
