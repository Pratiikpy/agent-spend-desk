# The language surcharge and the locale route (DF-043, DF-033), 2026-10-25

A model reads text as tokens, and the same sentence is more tokens in some scripts than in others. The Desk measures what a prompt in another script costs over the same length of English, on the same model, says when it has too few prompts to say, lists the extra as a waste class, and tests one way to avoid it: translate the task to English, work, translate the answer back.

## What it reads, and what it keeps

When a log is read, each prompt a person wrote is counted and given a script label (`src/desk/lang/script.ts`): code points, letters, and the Unicode script of the letters. The label is `en` for Latin script with English function words in it, `latin` for Latin script that is not shown to be English (code, a short fragment, French), one of fifteen scripts for the rest, `mixed` for two non-Latin scripts neither of which carries the text, and `none`. A script that carries less than 30% of the letters does not name the prompt, so a Japanese prompt with English identifiers is Japanese. Combining marks count with their letters, which a first version did not, and it made Hindi look like punctuation. The text is read once and not kept: the ledger holds `chars`, `letters` and `script` for each prompt (schema 30), nothing else. Ledgers read before this are filled in by `desk ingest --backfill`, which never replaces a value already there.

## What it measures

A task is a prompt and the first call the model made after it. Everything before the prompt is in the cache, so what the call newly read (uncached input and cache writes) is the prompt plus a few hundred tokens of harness text that is English whatever the prompt is. On each model the English tasks are fitted as tokens = a + b x characters, by the median of the slopes between pairs (a few odd tasks do not move it): `a` is the harness text, `b` English's tokens per character. A task in another script is then read as (tokens - a) per character, and its ratio to `b` is the surcharge. Only within one model, because the tokenizer is the model's. A cell is shown only with 20 tasks in it and 20 English tasks on the same model, and when the English prompts differ enough in length to fit; otherwise the answer is "not enough data" with the counts. Prompts under 100 characters, prompts that are mostly not letters (a pasted log, code), calls that read far more than the prompt (a restored context), a session's first prompt, and subagent calls are set aside, and the counts of each are printed.

The extra tokens are priced at the share of what the call paid for the tokens it newly read. They are listed as the waste class C-LANG when a cell costs 1.15 times English or more, for calls no other rule has already counted, with low confidence: the language may be the one the work needs. `desk language`, the Language section of the Bill screen (only when the period holds a prompt in another script), and `desk waste` show it.

## What was run

Against a ledger with it planted (`src/desk/sample/language.ts`: five scripts on three models, 180 tokens of harness text, 6% noise, cells with 6 to 60 tasks): every cell with enough tasks comes back within 8% of its planted ratio (Japanese 3.14 against 3.20, Devanagari 5.49 against 5.60, Cyrillic 1.96 against 2.00, Arabic 2.37 against 2.40, Japanese on the second model 2.00 against 2.00), the English line on each model is recovered (harness text 177 and 178 tokens against 180, slope within 3%), the four cells with too few tasks are withheld without a figure (one of them for want of English on its model), and every prompt is labelled with the script it was written in. `desk prove` runs it as `language-surcharge-recovers-the-planted-cells-and-withholds-the-thin-ones`. Mutation checks: dropping the harness text from the rate fails the ratio tests, and lowering the minimum fails the withholding tests.

On this owner's own ledger, a year of 3,763 log files and 455,613 calls, there is no prompt in another script, so the report says so and C-LANG is silent. The English fit on real Claude Code logs comes out at 0.41 to 0.51 tokens per character with 48 to 386 tokens of harness text, depending on the model. 1,496 prompts of Latin script were set aside because the rule did not show them to be English (informal or very short English among them): they are not in the baseline.

The other waste classes that had never fired were run on the same ledger on 2026-10-25, with pull request facts read through the owner's own `gh` (`desk landing --prs`: 2 repositories found from session folders, 194 commits, 15 pull requests read, none closed without a merge). C-ABANDON, C-REVERT and C-PR report none, and C-LANG reports none. That is a finding about this ledger and not a proof that the rules work: each fires on its planted case in `tests/desk/waste.test.ts`, `tests/desk/waste-outcomes-ledger.test.ts` and `tests/desk/prs.test.ts`. Only two repositories were found, so a fuller scan could change it.

## The locale route, and a fault that was found in the experiment itself

The localised tasks are sixteen of the canary tasks whose answer is a number, written out in Japanese and in Hindi (`data/locale/tasks.json`); the loader refuses a translation whose figures differ from the English original, and it found four that did. Three arms run on one model with the canary's own checkers: the English original (it must be answered right at least 90% of the time for any comparison to be made), the task as written, and the route (a translation call, the work call on the English, a translation call back). The route is judged against the task as written by a paired difference with an interval that resamples the tasks in clusters (10,000 draws, seeded) against a margin of 5 points.

The first recorded run said the route lost a third of the answers (60% right against 94%) and used 157% more tokens. That was a fault of the experiment. The translation call had been given the task bare, and the model answered it instead of translating it (it returned `23.05`, and a wrong answer, as the "English" of a Japanese arithmetic question). Reading the three steps of the failing tasks found it before it was reported. The instruction now puts the text between tags, says it is a task for someone else that is not to be solved, and shows two worked examples in each language, with figures that are in no task; the run was recorded again from nothing. The old verdict is not used anywhere.

The recorded run (`nvidia/nemotron-3.5-super-120b-a12b` through NVIDIA's API, three repeats of each of 16 tasks, 240 attempts, none without an answer): English 100% right. In Japanese the task as written is 91.7% right and the route 100%; in Hindi 95.8% and 100%. The differences, route minus as written, are 8.3 points (interval 0.0 to 21.4) and 4.2 points (0.0 to 11.1): the verdict in both is inconclusive, because the intervals reach past the margin of 5. They do not show the route better or equivalent. Tokens: the call that does the task takes 14% and 16% fewer tokens through the route (90 against 77 and 92 against 77), because Nemotron's tokenizer makes Japanese and Hindi only about 1.2 times English on these tasks; the whole route takes about six times the tokens, 540 of them in the translation calls, most of which are the worked examples. The part of the route a cheaper model would carry is that 540. Nothing is priced, because the free tier's price is not published.

`desk prove` replays the recording through the same code and compares it row for row with `docs/verification/language/locale-route.json`, then makes every answer of the route wrong (the verdict must be worse), makes it answer exactly as the written task did (equivalent), and makes English fail (withheld).

## Not covered

- Real prompts in another script: none exist in this owner's ledger, and the planted ledger is the only evidence that the measurement recovers a surcharge. The harness text is assumed to be the same in every language, and the rate of prompts with pasted content in them is only partly filtered.
- Claude's tokenizers. The recorded experiment is on Nemotron, whose tokenizer is kinder to these scripts than the planted Claude ledger assumes; nothing here says what the route would do on Claude.
- Tasks that are not arithmetic with a numeric answer: the sixteen tasks are all of that kind, and the translation of a long or technical prompt, a prompt with code in it, or a reply that is prose was not tried.
- Languages other than Japanese and Hindi, and translations written by anyone but the people who built the experiment. The two worked examples in each language are also theirs.
- A dedicated translation model. The translation calls here are the same chat model, with worked examples.
- A price: the route's saving in dollars is not computed.
