# Would a cheaper model have done the same work? (DF-042)

`desk swap run --baseline NAME=MODEL --candidate NAME=MODEL` gives each of the owner's accepted tasks (work from their history, with the tests that decide it) to two models in a sandbox copy of the repository, three times each. The model works with seven tools (Read, Glob, Grep, LS, Edit, Write, RunTests); every other call is answered from the recorded session or stops the run (see `replay-sandbox-2026-10-25.md`). Each run is graded by the tests that decided the original task, laid over whatever the model wrote, so a model cannot pass by writing its own test. The report is a paired comparison clustered by task, with a 95% interval widened for the number of clusters; a call of "as good" needs at least 8 clusters, a margin of 5 points and a baseline that reproduces at least 90% of the passes the recorded work had. Without that, the verdict is **withheld**. The report is a function of the stored items and is made again from them each time it is read.

## The run that was made (2026-10-25)

Baseline `nvidia/nemotron-3.5-super-vl-120b-a12b`, candidate `nvidia/nemotron-3.5-lightning-30b-a3b`, through NVIDIA's free API, on the ten tasks of the Lab (small repositories with hidden tests, all with a strong oracle), three runs each: 227 live model calls. The record is `docs/verification/swap/run-992eb04991.json` (results and statuses only; no prompts, patches or recordings).

- The larger model passed 57.1% of its 21 scored runs (12 of 21; 9 runs ended in an API error or timeout and are not in the figure). The comparison needs 90%, so **the verdict is withheld**. The difference from the cheaper model (-11.1 points, interval -32.9 to +10.7, 9 paired tasks) is printed but is not a finding.
- The cheaper model passed 34.5% of 29, using about 5.5 times the tokens a run (111,904 against 20,138), because it ran out of turns more often.
- What this says: on this harness neither model reproduces the recorded passes, so nothing about the cheaper one can be concluded from it. It does not say the cheaper model is worse; it says this run cannot tell.

Defect found by the run: two processes were writing to it (a resumed run whose first process had not stopped), and the stored report had counted 11 passes where the stored items hold 12. A report is now made from the stored items (`recomputeReport`), so a run that was resumed or written to twice reports the same; the first report of this run was replaced, and `tests/desk/replay-run.test.ts` covers it. The `desk prove` check `recorded-live-swap-recomputes-and-withholds-what-it-cannot-support` recomputes the counts and rates from the stored items and checks the withholding rule.

## Tested

`tests/desk/replay-run.test.ts` (19): a model that does the work passes and one that does not fails; a model cannot pass with a test of its own; a call that could change the world stops the item as not comparable; the paired statistic against a known answer (including a small-sample correction after the plain percentile bootstrap covered 92% of the time); equivalence withheld on fewer than 8 clusters; a known-worse route found worse; the same model on both routes found equivalent; resume; and the report recomputed.

## Not covered

The baseline was not reproduced, so a "better", "as good" or "worse" verdict has not been seen on a real pair of models. Nine of thirty baseline runs failed on the API (429 and timeouts); the free API allows about two calls at once. The run used the Lab's tasks, not the owner's own; the owner's history had 3 kept or merged sessions and none with tests that fail before and pass after (`task-capture-2026-10-25.md`). Costs in dollars were not measured: the free API has no price.
