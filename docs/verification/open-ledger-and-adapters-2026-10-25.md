# The open ledger format and the adapter SDK (2026-10-25)

Feature DF-063. The format is `desk.events/1` ([docs/open-ledger-format.md](../open-ledger-format.md), [the JSON Schema](../schema/desk-events-1.schema.json)); the SDK is described in [docs/adapter-sdk.md](../adapter-sdk.md). Commands: `desk events validate | import | export | schema` and `desk adapters list | test | import | init`.

## What it does

- **A strict, versioned file.** Header, sessions, calls, one JSON object to a line. Every line is checked and a problem is reported with its line number and field; a file with any invalid line is refused whole and nothing from it is stored. A schema newer than the reader's is named as such. A value not known is left out or null, never zero. There is no field where a prompt, a tool result or an estimate could go.
- **Into the ledger** (`ingest_source` kind `events`, schema 24). Calls are filed as `ev:<tool>:<id>`, priced at list price from their tokens, a cost the tool reported is kept beside the estimate, cache writes with no stated lifetime are priced as 5-minute writes and counted, a secret in a folder or branch name is masked, the ledger chain is checked before and sealed after, and reading a file again stores nothing twice. A file that claims to be from a source the Desk reads itself is refused, so no call is counted twice.
- **Out of the ledger.** `desk events export` writes the record as the same format and reads the file back before saying it is done. Folders and branches are left out unless asked for. The export will not overwrite a file.
- **Adapters.** A folder with a manifest, a module with `detect` and `parse`, a real sample file pinned by its hash, and golden outputs. An adapter is loaded only if its manifest and paths are sound, its sample is the pinned file, every golden file is reproduced byte for byte on two runs, its output is valid, and `detect` says true for the sample and false for an empty file, for an unrelated JSON object and for a `desk.events/1` file. An adapter built from a sample marked `constructed` passes its tests and will not import: an adapter exists only when it was built from a real sample.
- **The sandbox.** An adapter runs in a process of its own with Node's permission model on, an allow-list of built-in modules, no `fetch`, 30 seconds, 512 MB, an empty environment and nothing out but its JSON reply. If this Node cannot start with the permission model, no adapter is run.

## What ran

- `tests/desk/open-events.test.ts` (18): a valid file; twenty ways a record can be wrong, each with its line and field; header rules and a newer schema; repeated ids; the line limit; fifty problems listed and the rest counted; blank lines and Windows line endings; unknown as null; the writer's fixed key order and byte-stable output; the JSON Schema against the reader (the same fields, the same required ones, the file in `docs/` equal to what the code generates); into the ledger (ids, pricing, cache basis, reported cost, session, source kind, chain intact; a second read and an overlapping file store nothing twice; two tools with the same call numbers kept apart; an invalid line writes nothing; native sources refused, including by a session's tool; a secret masked); out of the ledger (no estimate, prompt or folder, token sums equal the ledger's, folders only on request, no overwrite, an empty range said, a tool filter, the Desk's own export refused on the way back in); the commands.
- `tests/desk/open-adapter.test.ts` (22): the sandbox against reads outside the folder, writes anywhere, fourteen network, process and module imports, `fetch`, `process.binding`, native addons, a loop that never ends and an adapter that throws; the manifest rules; the reference adapter loading with both golden files; a golden changed by one token, a swapped or missing sample, a sample no fixture runs on, paths that leave the folder, a `detect` that claims everything or nothing, a parse that is not deterministic or not valid, an adapter that imports the network, calls `fetch`, or reads outside its folder; a root with a good and a broken folder; the import path with a real-marked copy (skips said, chain intact, second read adds nothing, a file that is not the tool's, a missing file, an adapter not loaded, a file over the size limit); `init` and `--write-golden` (never over an existing golden); and the real command line.
- `desk prove`, check `open-format-and-adapter-harness-refuse-what-is-broken`: the sample ledger (97,843 calls on this run) written as `desk.events/1` and read back clean with the same token sums; the reference adapter reproduced both golden files in the sandbox; four broken copies each refused for the reason expected.

## Defects the tests found

- **The sandbox's import list let `node:http2` through.** The first hook matched module names with letters and underscores only, so a name with a digit was not recognised as a built-in and passed. Found by the sandbox test; the hook now asks Node whether a name is a built-in (`isBuiltin`) and passes only the short list, and the test covers `http2`, `inspector`, `perf_hooks`, `v8` and a package name.
- **The first import wrote the chain's digest column itself,** which the ledger chain reads as the digest of a source's calls, so the second import failed the chain check. It now leaves that column to the chain, as the other readers do.
- The built-in `module` is not on the allow-list: an adapter that could import it could register a hook of its own that undoes the restrictions.

## Not covered

- **No adapter has been built from a real sample of a real tool.** The one shipped adapter reads a made-up tool and is marked `constructed`; it demonstrates the harness and cannot import. NOT VERIFIED against any third-party tool's file.
- The sandbox rests on Node's permission model, which has not been audited here, and the allow-list of built-ins. It was tested against the escapes listed above, not against a determined attacker. A hostile adapter is not made safe; the document says to read an adapter before running it.
- Network access is stopped by the import hook and by removing `fetch`, not by the permission model (Node 24's has no network control). A route not covered by either would not be caught by the tests above.
- The `origin` of a sample is the author's statement. The Desk checks the file is the pinned one, not that it came from a real run.
- The export is one file of at most 1,000,000 records; a larger ledger is exported in date ranges by hand.
- A tool written in another language was not asked to produce a file: the JSON Schema was checked against the reader's own rules and a file written by the Desk's exporter, not against an independent writer.
- Windows was the only operating system the sandbox was run on in this session.
