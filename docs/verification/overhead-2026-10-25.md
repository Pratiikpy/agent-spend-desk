# Shared overhead: idle and unowned spend, shared by the projects that landed work (2026-10-25)

Feature DF-095 built. `desk overhead` and a Shared overhead section on the Bill screen.

## What is shared, and among whom

**Overhead** is the cost of two kinds of call that no project's tasks own: **idle work** (a call with no prompt behind it, no tool result waiting for it, more than 30 minutes after your last prompt: the autopsy's own definition) and calls in **sessions with no project folder**. A call is counted once; an idle call is overhead even in a project that landed work.

**Landed spend** of a project is what the rest of its sessions cost, for the sessions whose work reached a bar. The spec asks for work kept for days; the default is `kept`, and `--landed committed|merged` lowers it, because a lower bar is the owner's to choose and the report says what each bar would have done.

The allocation is OpenCost's: `A_p = floor(U × V_p / ΣV)` for each project with landed spend, and the few micro-dollars the floors leave go to the project with the most landed spend, so the shares add up to the overhead exactly. The products are formed in BigInt, because overhead and landed spend are each near 10^10 micro-dollars and the product passes 2^53. A project that landed nothing bears none of it. When no project landed anything, the whole overhead stays **unallocated**: it is never divided by guess and never dropped.

## What ran

`tests/desk/overhead.test.ts` (11): the proportions, the residual and its tie-break, 400 random splits all summing exactly to the overhead, a case past 2^53, the all-zero and empty cases, a project named twice, refusal of fractions and negatives, and the view built from a ledger (idle and unowned calls are overhead, every call is in exactly one place, a lower bar shares among more projects, nothing at the bar leaves it unallocated and says what a lower bar would do). `ui/overhead-ui.test.ts` (3). The Bill screen was photographed in light at desktop width, console clean.

On this machine: September 2026, $155.28 of overhead, all of it idle work, over 17 sessions; October, $60.94 over 420 sessions. Both are shared by **one** project, `fhenix builder`, because it is the only project with work at the bar: the ledger holds 3 sessions with any linked commit (1 kept, 2 merged), so "landed" is nearly empty here. At the lower bars October's overhead would be shared among two projects.

## Not covered

- **The weights rest on the commit links the ledger holds, which are few on this machine.** A project whose work landed but was never linked bears none of the overhead, and the report says so every time it prints. This is the input being sparse, not the arithmetic being wrong: the arithmetic conserves to the micro-dollar in every case tried.
- `kept_n_days` as the spec words it is read as the `kept` state the outcome linker assigns; the number of days is the linker's, not set here.
- Shared overhead is idle work and unowned calls only. Other candidates (a coordinator's own work, a tool's fixed fee) are not counted; the Desk has no record of them.
- The spec's `overhead_allocations` table is not kept: the allocation is computed from the ledger when asked, and so cannot go stale.
- Allocation is by project folder name, so two folders with the same name share one row.
