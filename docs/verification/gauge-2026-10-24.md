# The live gauge (2026-10-24)

`desk gauge` answers "what is this costing me right now?": the spend over the last few hours (five by default), the rate over the last 30 minutes, where it went by cause, and where the plan windows stand. `--line` prints one line for a status line or a prompt, `--watch` keeps it fresh, `--session <id>` limits it to one session, `--hours N` changes the span.

## What it reads, and what it will not show

- **Every figure is read from the ledger** the Desk already keeps, so the spend equals the Bill and the autopsy for the same span (the test compares it with a direct sum of the cost events). The split is the autopsy's causes, and the parts add up to the spend.
- **A figure the sources do not have is a dash with the reason, never zero.** No call in the last 30 minutes gives no rate, not `$0.00/h`; calls with no price are counted and the spend is called a floor; a span with no call is `$0.00` with a note saying it is zero, not unknown.
- **A plan reading older than ten minutes is not shown.** The Claude Code status line's newest reading and the readings Codex writes into its logs are both dropped after ten minutes, with a sentence saying how old the last one was. A window that has already reset is never shown. A status line payload that sends an epoch timestamp, a negative number or a value over 100 as a percent is rejected, not shown as 1,761,300,000%.
- **The pace is not a forecast.** For a window with a recent rise the gauge says when it would reach 100% at the pace of the last hour, labelled as a pace; the forecast of whether the window will last is `desk runway`, from past windows of the same plan.

## Keeping it fresh

`desk gauge` first reads what was appended to the logs since the last read, then draws. `--watch` polls the logs' modification times every three seconds and redraws when one changes; `--watch` also writes a small cache (`~/.desk/gauge.json`, or `DESK_GAUGE_CACHE`) that the Claude Code status line command reads to add `$X/h · $Y/5h · biggest cause N%` to its line without opening the ledger. The cache is ignored once it is ten minutes old, and the status line is exactly as before when there is none.

## A defect found by using it

The first run of `desk gauge` on this machine's real ledger took **3 minutes 38 seconds** every time, though almost nothing had changed. Reading logs looked up the newest call of every file with a query that scanned the whole call table (450,000 rows) once per file (3,758 files), and opened a transaction for files that had not grown. Two changes: a file whose size equals the offset it was last read to is skipped before anything else, and the lookup has an index (`model_call (source_id, ts)`, schema version 10). The same command now takes **2.5 seconds**. Every command that reads logs (`card`, `ingest`, `landing`) gets the same speed-up. Tests: an unchanged file reads no line and leaves its record untouched, a file that grew is still read, and the lookup's query plan uses the index.

## What was run

The gauge on this machine at 18:19 UTC: $61.01 over five hours, 597 calls, the last four minutes ago, $23.95 an hour over the last 30 minutes, 50% new work and 44% re-reading the conversation, two calls without a price. The tests (`tests/desk/gauge.test.ts`, `tests/desk/gauge-watch.test.ts`) cover the arithmetic to the micro-dollar, each dash, the staleness limits, the session filter, a different span, the Codex readings and the pace, the watch loop (it draws at the start and again only when a log changed), the cache, the real status line command with and without a cache, and the CLI.

## Not covered

No status line reading has been captured from a real Claude Code session, so the plan percent on the Claude side has been shown only from constructed payloads in the Desk's own tests and not against real Claude Code. The menu-bar widget in the specification was left out, as the specification itself says.
