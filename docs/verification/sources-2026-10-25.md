# Sources: discovery, a gateway's spend log, OpenTelemetry spans, and Codex counters that disagree (2026-10-25)

Four features that decide what the Desk can read and how honestly it says so.

## DF-001: what the Desk finds, and what each source can tell

`desk sources` looks for every adapter's source where the tool normally keeps it (Claude Code in `CLAUDE_CONFIG_DIR` entries, or `~/.claude/projects` and `~/.config/claude/projects`; Codex in `CODEX_HOME` or `~/.codex/sessions`; OpenCode in `XDG_DATA_HOME` or `~/.local/share/opencode`; the Claude Code status line's log) and says, for each, how many files, how large, and when they changed (the files are not opened), what was searched when nothing is found and the option that names another place. Each source carries a **capability declaration**: nine things (tokens, the cache split, the tool's own cost, tool results, your prompts, plan limits, delegated agents, speed and geography, folder and branch), each yes, partly or no with the reason. A source that does not carry a thing leaves a gap in the Desk, never a zero. Tools the Desk knows exist and cannot read are listed with why: Gemini CLI, Cline and Cursor (no adapter written), and GitHub Copilot CLI (its local store holds turns and no token counts, checked 2026-10-24). The Doctor screen shows the same declarations beside what the ledger has read.

On this machine it found 3,758 Claude Code log files (7.4 GB, changed 2026-07-03 to 2026-10-24), 87 Codex files and the OpenCode database.

**A claim found false and corrected.** OpenCode's own cost per message was parsed and described as kept, but never stored. It is now stored beside the estimate when above zero (a zero is OpenCode's way of saying it did not price the call, so it is not kept), and the declaration says so.

## DF-023: a gateway's spend log

`desk gateway import <file>` reads a LiteLLM `LiteLLM_SpendLogs` export (JSON, JSON Lines, or CSV, with the column names matched in any case or spelling). Each request becomes a call of a tool called `litellm`, priced at list price from its tokens; the cost the gateway reports is stored beside it (a new table, `call_reported_cost`, schema version 13) and replaces nothing; `desk gateway summary` sets the two side by side per model. The cache is split out of the prompt count when the row's usage object says it; otherwise every prompt token is priced as fresh input and the rows are counted, because that overstates a model whose cache reads cost less. Not read: a request served from the gateway's own cache, a failed request, a row with no id, model, time or token counts, a repeated request id (read once); a negative or missing cost is no cost. The conversation, key, address and team columns are never read, whatever the file holds, and a person's name becomes a pseudonym in the session id. Unknown columns are listed. Reading a file twice, or a renamed copy, adds nothing.

## DF-022: OpenTelemetry GenAI spans, both ways

`desk otel import <file>` reads an OTLP/JSON export (one document, or one per line). Each leaf span that made a model request and carries token counts becomes a call. A span with none is a gap; a parent that totals its children's usage is skipped (counted once, at the leaf); spans of unsampled traces are left out and counted; the current and the earlier attribute names are both read; cache tokens are taken out of the input count for providers that include them and left apart for Anthropic's convention; a cost attribute under any of a few spellings is kept as the exporter's reported cost; prompts and completions are never read. `desk otel export` writes the Desk's own record as spans (a session span, and a span per call carrying the tokens, the model and `desk.cost.estimated_usd`, `desk.cost.class`, `desk.cost.snapshot_id`, `desk.cost.reported_usd`, `desk.task.id`, `desk.outcome.state`), with the cost on the calls only. **Not emitted**, because nothing in the ledger holds them: `desk.budget.reservation_id` and `desk.retry_of`. An export read back gives the same calls, tokens and estimated dollars.

## DF-021: Codex counters that disagree with themselves

A call is still the growth of the session's cumulative total. When a part of the count went down while the total went up, or more of the input was cached than the input grew by, the part is clamped to zero as before and the call is now flagged `inconsistent_buckets` (stored as a usage conflict and counted in the ingest report). More tokens in one reading than any request holds are flagged `implausible_size` and kept. When the total itself goes down (the counter restarted), the new reading becomes the base: before, every later reading below the old high-water mark counted nothing until it caught up, so a restarted counter silently dropped the rest of a session.

## Not covered

- **No real LiteLLM export, and no real OpenTelemetry export from an SDK, has been read.** The fixtures follow the documented columns and attribute names. A real export is the one thing both adapters have not met; the first real file may carry a spelling or a shape not listed here.
- The version of the OpenTelemetry GenAI conventions each exporter followed is not recorded in a span, and the specification was not checked here: NOT VERIFIED. Two SDKs' spans are not tested separately.
- Prices: OpenAI models have no price rows, so Codex and gateway calls on them are counted and unpriced.
- No Codex log from this machine has an inconsistent counter that is known; the flags were tested on constructed readings.
- Gemini CLI, Cline and Cursor have no adapter.
- A Claude Code `CLAUDE_CONFIG_DIR` listing several folders was tested with a comma; a colon-separated list is read on POSIX only.
