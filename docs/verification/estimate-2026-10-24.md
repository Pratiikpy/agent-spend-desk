# The pre-run estimate (2026-10-24)

`desk estimate [--type T] [--repo PATH] [--cap USD]`, and an `estimate_cost` tool on the gate's MCP server (`desk gate mcp --policy FILE --ledger FILE`), answer "what has a task like this cost before?" with a range, how many tasks it rests on, and how often that kind of range has held. They answer no estimate when they cannot answer honestly.

## The rules

- **Never a point.** A result is the 10th to the 90th percentile and the middle of similar past tasks, with the number of tasks and the dates they finished. The text says the top of the range is not a ceiling: one task in ten costs more.
- **Fewer than ten similar tasks is no estimate.** The output says "no estimate: fewer than 10 similar tasks (the most any comparison had is N)" and prints nothing in its place. This holds for the command, for the MCP tool and for an empty ledger.
- **Similar means, in order:** the same type in the same repository, the same type anywhere, the same repository, any task. The first with ten or more tasks is used and the output lists what each one had and which it used.
- **Type.** The part of the branch before the first slash (`fix/cart` is `fix`), a ticket's project key, the text before a colon in a label set with `desk task`, else the label. Tasks are the groups from `desk task` (see the Outcomes screen).
- **Weighting.** With more than five tasks a task counts half as much for every 30 days it is old, so an old costly habit fades. The tail is kept: the planted costly task stays in the cohort and shows in the chance of crossing a cap, rather than being trimmed to make the next task look cheaper.
- **The scorecard.** For each task from the eleventh on, the range computed from the tasks before it is compared with what the task cost, and the output says how many held. The range is meant to hold about 80%. Under twenty later tasks it is called a small sample.
- **A cap.** With `--cap` the output says what share (weighted the same way) of the similar tasks cost more than it.

## What was run

- 16 tests of the percentiles, the weights, the chain, the tail, the scorecard and the output (`tests/desk/estimate.test.ts`) and 4 of the MCP tool (`tests/desk/gate/mcp-estimate.test.ts`): it is listed read-only, it answers a tool error that says what is missing (not a gate failure) when the server has no ledger, no estimate for a ledger with too few tasks, and a range with its task count for one with enough.
- On this machine's ledger: `desk estimate --type fix` found no task of type `fix` (this machine has no `fix/` branches), fell through to the 366 tasks in the repository, and answered **$0.27 to $0.86, middle $0.45**. Its scorecard on this ledger: the range held the real cost in **288 of 356 later tasks, 81%**, against the 80% it aims at.

## Not covered

Those 366 tasks are almost all single sessions: with no feature branches, no ticket keys and no label, each session is its own task, so the estimate here is the cost of "a session", not of a kind of work. A type-specific estimate has been tested on constructed tasks and has not met real labelled work. The scorecard is a rolling backtest on one person's history; it is not a claim about anyone else's, and 81% of 356 has an interval of roughly 77% to 85%. The chance of crossing a cap is a share of past tasks, not a forecast of this one.
