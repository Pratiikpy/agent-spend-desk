## 1. What it is
Container and artifact signing, attestation, and verification CLI and Go library supporting ephemeral keyless OIDC identities, KMS, hardware tokens, and transparency logs ([README.md:16-32](https://raw.githubusercontent.com/sigstore/cosign/main/README.md#L16-L32)). Apache-2.0 (`LICENSE:1-169`).

## 2. Architecture map
- **CLI Layer**: `cmd/cosign/cli/` defines subcommands for `sign`, `sign-blob`, `verify`, `verify-blob`, `verify-attestation`, and `bundle` (`cmd/cosign/cli/commands.go:45-120`).
- **Verification Engine**: `pkg/cosign/verify.go:829-976` (`verifyInternal`), `pkg/cosign/verify_bundle.go:24-43` (`VerifyNewBundle`), and `pkg/cosign/verifiers.go:33-97` coordinate signature, identity, and claim validation.
- **Key & Signer Abstraction**: `pkg/signature/keys.go:43-120` resolves KMS URIs, PKCS#11 hardware modules, and local files into `signature.SignerVerifier` interfaces.
- **Bundle Packaging**: `pkg/cosign/bundle/` and `cmd/cosign/cli/verify/verify_bundle.go:46-185` assemble detached signatures, timestamps, and Rekor proofs into Sigstore bundle v0.3 formats.
- **Data Flow**: Caller provides artifact digest + signature/bundle → verifier loads trust roots (`root.TrustedMaterial`) → validates envelope signature → checks transparency log (SET) and TSA timestamp → executes claim verifier against subject digest.

## 3. Features and how each behaves
- **Keyless Signing**: Exchanges OIDC identity tokens for short-lived X.509 certs via Fulcio and records signatures to Rekor (`pkg/cosign/bundle/sign.go:41-69`).
- **Attestation Wrapping**: Encapsulates in-toto statements (provenance, SBOM, vulnerability scans) inside Dead Simple Signing Envelope (DSSE) payloads (`specs/ATTESTATION_SPEC.md:10-45`, `pkg/cosign/attestation/attestation.go:51-98`).
- **Offline Verification**: Enabled via `--offline` flag; forces verification against self-contained bundles and locally pinned `trusted_root.json` without network access (`pkg/cosign/verify.go:859-863`, `cmd/cosign/cli/verify/verify_blob.go:113-165`). Fails immediately if online Rekor lookup is required (`pkg/cosign/verify.go:861-863`).
- **Policy Enforcement**: Unmarshals verified DSSE statements to JSON and evaluates them against OPA Rego rules querying `data.signature.allow` or CUE schemas (`pkg/policy/attestation.go:58-120`, `pkg/cosign/rego/rego.go:28-40`).
- **Failure Behavior**: Missing certificates, mismatched subject digests, or missing timestamp proofs raise explicit typed errors (e.g. `VerificationFailure`, `ErrNoCertificateFoundOnSignature`) (`pkg/cosign/verify.go:894-896, 967-970`).

## 4. How people use it
Installed as a standalone binary or Go module (`go install github.com/sigstore/cosign/v3/cmd/cosign@latest`, NOT VERIFIED). Users run `cosign sign` to attach signatures to OCI registries or `cosign sign-blob --bundle out.bundle` for local files. Verification uses `cosign verify --key cosign.pub` or `cosign verify-blob --bundle <path> --trusted-root <path> --certificate-identity <email> --certificate-oidc-issuer <url>` (`doc/cosign_verify-blob.md:20-65`).

## 5. Mechanism for the Desk (M9 Ledger & Offline Verifier, M13 Release)
- **Key Handling**: Supports password-encrypted PEM private keys using `scrypt` (`ENCRYPTED COSIGN PRIVATE KEY`, `pkg/cosign/keys.go:43-53`), cloud KMS providers (`aws-kms://`, `gcpkms://`, `azurekms://`, `hashivault://`, `pkg/signature/keys.go:43-58`), and PKCS#11 hardware keys (`pkg/signature/keys.go:110-120`).
- **Bundle Format**: Emits Sigstore Protobuf Bundle v0.3 (`application/vnd.dev.sigstore.bundle.v0.3+json`, `specs/BUNDLE_SPEC.md:41-80`, `pkg/cosign/bundle/constants.go:17`). The bundle integrates: (1) content (`messageSignature` or DSSE `dsseEnvelope`), (2) verification material (`X509Certificate` or public key hint), (3) Rekor transparency log entries with SET inclusion proofs, and (4) RFC 3161 TSA signed timestamps (`cmd/cosign/cli/verify/verify_bundle.go:58-185`).
- **What Verification Proves**:
  1. *Cryptographic Authenticity & Integrity*: Proves the exact signed payload or DSSE envelope was generated by the specific keyholder or authenticated OIDC identity (`pkg/cosign/verify.go:926-929`).
  2. *Artifact Binding*: `IntotoSubjectClaimVerifier` proves the signed in-toto statement specifically targets the artifact's SHA-256 digest (`pkg/cosign/verifiers.go:79-96`).
  3. *Timestamping & Non-Repudiation*: Proves via RFC 3161 timestamps or Rekor SET inclusion that the signature existed during the certificate validity window before key expiration or revocation (`pkg/cosign/verify.go:834-843, 947-960`, `pkg/cosign/bundle/sign.go:135-139`).
- **What Verification Does NOT Prove**:
  1. *Content Truth*: Does NOT prove the attestation payload itself (e.g. SLSA build claims, audit logs, vulnerability scans) is accurate or uncompromised—only that the identity signed it.
  2. *Unbound Artifacts*: When claims checking is disabled, `WithoutArtifactUnsafe()` verifies envelope signature validity without verifying that the envelope describes the artifact presented (`cmd/cosign/cli/verify/verify_blob_attestation.go:217-218`).
  3. *Context Binding*: Does not prevent replay of a valid signature in a different environment unless repository annotations are explicitly verified (`pkg/cosign/verifiers.go:49-53`).

## 6. Agent patterns
No autonomous LLM loops or agents. Cosign functions as a deterministic cryptographic gatekeeper. Downstream agent systems invoke Cosign to verify tool attestations and validate signed release artifacts before execution.

## 7. Model and data layer
Zero LLM or embedding dependencies. Integrates with OCI registries (distribution-spec referrers API, `specs/BUNDLE_SPEC.md:95-164`), TUF root metadata repositories (`pkg/cosign/tuf.go:20-60`), and Rekor REST APIs (`pkg/cosign/bundle/sign.go:116-134`).

## 8. Hackathon-care checks
- Pure Go implementation runs fully offline with `--offline --bundle <file> --trusted-root <file>` (`pkg/cosign/verify.go:859-863`).
- Deterministic cryptographic test suites with static testdata vectors (`pkg/cosign/verify_test.go:30-120`).
- No hardcoded secrets or credentials; CLI sanitizes private key passphrases via terminal prompts (`pkg/cosign/keys.go:68-69`).

## 9. Traps seen
- **Unsafe Claim Skipping**: `verify-blob-attestation` permits `WithoutArtifactUnsafe()` if claims checking is omitted, creating a critical vulnerability where any valid signed envelope validates an arbitrary payload (`cmd/cosign/cli/verify/verify_blob_attestation.go:217-218`).
- **Dual Bundle Fragmentation**: Codebase maintains dual verifiers for legacy JSON `RekorPayload` and Sigstore Protobuf Bundle v0.3 (`pkg/cosign/verify.go:1286-1349`, `pkg/cosign/verify_bundle.go:24-43`).
- **Ambient Expiry Fallback**: Without a verified timestamp or tlog entry, expiry validation falls back to `time.Now()`, vulnerable to client clock manipulation (`pkg/cosign/verify.go:963-973`).

## 10. Reuse
Apache-2.0 (`LICENSE:1-169`). We can reuse Sigstore bundle v0.3 data models, DSSE envelope handling, and offline root verification patterns with attribution.

## 11. Verdict: ADAPT bundle v0.3 and offline verification; REJECT unsafe claim skipping
- **Three things to copy**:
  1. Sigstore Bundle v0.3 structure (`application/vnd.dev.sigstore.bundle.v0.3+json`) unifying DSSE envelope, public key material, RFC 3161 timestamps, and transparency proofs (`cmd/cosign/cli/verify/verify_bundle.go:58-185`).
  2. Offline root-of-trust verification architecture using pre-cached `trusted_root.json` containing log and TSA trust anchors (`pkg/cosign/verify.go:859-863`, `pkg/cosign/verify_bundle.go:24-43`).
  3. `IntotoSubjectClaimVerifier` pattern enforcing strict SHA-256 digest matching between target artifacts and attestation subjects (`pkg/cosign/verifiers.go:59-97`).
- **Three things to avoid**:
  1. Allowing unsafe signature verification without artifact digest binding (`WithoutArtifactUnsafe()`, `cmd/cosign/cli/verify/verify_blob_attestation.go:217-218`).
  2. Splitting verifier logic between legacy ad-hoc JSON bundles and protobuf bundles (`pkg/cosign/verify.go:1286-1349`).
  3. Falling back to ambient `time.Now()` for certificate expiration checks instead of enforcing signed timestamps (`pkg/cosign/verify.go:963-973`).
- **Where the Desk is ahead**: The Desk binds policy versions, execution cost, token receipts, and approval rationale directly into its signed decision dossiers, whereas Cosign leaves semantic policy checks to external unbundled Rego/CUE scripts.
