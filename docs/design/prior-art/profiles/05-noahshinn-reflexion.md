## 1. What it is
The reference code for the Reflexion paper (2023): an agent that, after a failed attempt, writes a short verbal reflection and carries it into the next attempt. Two settings: HotPotQA reasoning (CoT and ReAct) and AlfWorld interactive tasks. MIT.

## 2. Architecture map
Agents step, fail, reflect, update memory, and try again. HotPotQA runs from notebooks; AlfWorld runs from `alfworld_runs/main.py` and `run_reflexion.sh`. Per-environment config holds a `memory` list of reflection strings, updated after each trial.

## 3. Features and how each behaves
Four strategies: none, last attempt, reflexion, last attempt plus reflexion. After a failure, a reflection prompt (task, truncated prior trace, few-shot examples) returns one text string diagnosing the failure and a plan. Memory starts empty, grows by one reflection per failed trial, and only the last three are fed back.

## 4. How people use it
HotPotQA: set the API key, pick a notebook and a strategy, run. AlfWorld: edit `run_reflexion.sh` (trials, environments, run name, memory flag), run it; logs go to a run folder; completed runs from the paper are in the repository. Issues and feedback: NOT VERIFIED.

## 5. Mechanism for our module (M5 critic and learning; M6 memory)
The reflection is generated by a separate model call that compares expected and actual outcomes and prescribes the next action. State is a plain list of strings per environment, capped at three, with the scratchpad trimmed to 1,600 tokens. Lost: the exact failed actions beyond the trace, and anything older than three reflections.

## 6. Agent patterns
Two model instances (actor and reflector) with separate temperature and token budgets; critic loop built into the run loop; no separate evaluator; no confidence branching. A failure in the reflection call is not caught, so the loop continues with an empty reflection (NOT VERIFIED beyond the reader's note).

## 7. Model and data layer
Model passed through a constructor (default gpt-3.5-turbo per the reader); Wikipedia lookup for ReAct; task data passed in per environment. Evaluation is exact match for HotPotQA and task success for AlfWorld.

## 8. Hackathon-care checks
Trace: scratchpad printed, AlfWorld writes per-trial JSON with success status and the reflections. No sample mode, no Docker. Evaluation numbers come from the paper; the logged runs are not tied to published figures with metadata (NOT VERIFIED). No injection defence noted. Key from an environment variable.

## 9. Traps seen
No quality check on reflection text before reuse; no handling of reflection failures; paper results not reproducibly linked to the logged runs.
