# Prior art 11: memory, consolidation and learning for agents (2023 to 2026 frontier)

> **Terminology note (added with spec v3).** This file was written before the trust model was fixed. Where it says T0 to T4 or `tier(derived) = min(inputs)`, read the lattice in `docs/design/00-architecture-master-spec.md` section 5: `SOR` (most trusted), `VERIFIED`, `EXTRACTED`, `UNTRUSTED`, with `combine` returning the least trusted input. Roughly: T0 and T1 here map to `SOR`, authoritative registry or tool-verified to `VERIFIED`, secondary web or model-extracted to `EXTRACTED`, adversary-authored to `UNTRUSTED`. The spec is authoritative; this file is a dated research record and is not rewritten.


Scope: what the field has learned about agent memory that bears on Plumbline's H-MEM precedent store, World Model facts, dreaming proposals and Markovian carryover. Companion to `prior-art/05` (Letta, mem0, LangMem, A-MEM, Generative Agents, Reflexion) and `prior-art/01` (HippoRAG, Graphiti, Cognee); those are not re-torn-down here, only their published evaluations are examined where the module brief asked for it.

## 1. Frame: what Plumbline's memory must do (from the spec, sections 7 and 10, and brief A.1 to A.3)

- **H-MEM** is the precedent store: sync conformance surface, trust ledger (17 action types), feedback deltas (+0.05, -0.03, -0.20), preview-first sleep, dreaming that only proposes.
- **World Model** holds bitemporal facts with provenance; resolution must be a pure function of the fold, not a side effect (brief A.2 gap 4).
- **Dreaming** is offline, proposals only, replayed over past cases; it cannot activate a rule, edit a case or change an autonomy cell.
- **Markovian** carries fact ids, never facts, across chunks.
- Known reference gaps we already have to close (brief A.1): sleep synthesis deletes sources and has no guardrails; dream text is concatenation; supersession never sets `supersededBy`; every query mutates state; no privacy filter before reinjection.

Three claims the literature below lets us state precisely:
1. LLM-driven consolidation is not safe by default; it can lower utility below having no memory (item 2.2).
2. The common memory benchmarks cannot tell us whether a precedent store works, and one is demonstrably flawed (section 9).
3. Memory poisoning defences that act on content or on additive provenance weights do not work well; defences that act on write-path structure and dependency tracking are the ones with evidence (section 6).

## 2. Offline consolidation, sleep-time compute, dreaming

### 2.1 Sleep-time Compute (Letta and UC Berkeley)
- What: let a model pre-process a persistent context between queries, so test-time compute per query falls. Letta later productised this as background "dreaming" subagents.
- Metadata: arXiv 2504.13171 (https://arxiv.org/abs/2504.13171), Lin, Snell, Wang, Packer, Wooders, Stoica, Gonzalez, 2025-04-17. Repo letta-ai/sleep-time-compute: 141 stars / MIT / 2025-04-30 / not archived (paper code and datasets only). Platform repo letta-ai/letta: 25121 / Apache-2.0 / 2026-09-10. Docs page https://docs.letta.com/guides/agents/sleep-time-agents says background agents edit git-backed memory blocks, trigger after N completed steps or on context compaction, and offer "agent reviews before applying".
- Idea: amortise inference across related queries; gain correlates with query predictability. Paper claims (author-reported) about 5x less test-time compute for equal accuracy on Stateful GSM-Symbolic and Stateful AIME, 13 to 18 percent accuracy gain from scaling sleep-time compute, 2.5x lower cost per query when amortised.
- Plumbline use: release decisions are highly predictable (same counterparty recurs, same policy). Sleep-time work should produce a derived `DossierCache` keyed `(counterpartyId, worldModelSeq, ruleVersion)` holding candidate precedent ids, rule dry-run fires and unresolved-conflict lists. Never decisions. Cache hit requires exact key match, otherwise recompute; cache content is tier T2 (derived) and is re-verified against the live World Model at decision time. This is the safe reading of sleep-time compute for a regulated decision path.
- Limits: benchmarks are synthetic stateful maths; no evidence for decision systems. Letta's dreaming edits memory in place, which is exactly what our spec forbids. We adopt the amortisation idea and reject the in-place edit.

### 2.2 Useful Memories Become Faulty When Continuously Updated by LLMs (PREPRINT, central to our thesis)
- Metadata: arXiv 2605.12978 (https://arxiv.org/abs/2605.12978), Zhang et al., submitted 2026-05-13, revised 2026-08-29. No code located.
- Idea: in an ARC-AGI task stream with three memory actions (Retain raw episode, Delete, Consolidate into an abstract store), utility first rises, then falls, and can drop below the no-memory baseline. Reported: GPT-5.4 failed 54 percent of previously solved problems when using consolidated memory; episodic-only memory matched or beat consolidated memory; disabling consolidation doubled accuracy against forced consolidation. Cause stated in the paper body: lossy rewrites drop useful detail and introduce spurious rules. Recommendation: raw episodes stay primary evidence; keep episodic and abstraction-forming roles separate; gate consolidation explicitly.
- Plumbline use: this is the empirical backing for three rules we should make hard invariants. (a) Case records are append-only and never rewritten by sleep. (b) Abstractions exist only as separate `RuleProposal` and `SummaryView` objects that point back to episode ids and can be discarded without loss. (c) A standing "consolidation-harm test" in our eval: run N dreaming cycles and plot decision accuracy on a held-out set; the curve must not decline (section 10, contribution B).
- Limits: single synthetic domain (ARC-AGI), one lab, preprint; an earlier fetch of the PDF returned a generic summary that contradicted the abstract and was discarded, the numbers above come from the abstract page and HTML.

### 2.3 Auto-Dreamer (PREPRINT)
- Metadata: arXiv 2605.20616 (https://arxiv.org/abs/2605.20616), Ye, Liu, Wang, Yu, Zhao, Liu, McAuley, You, 2026-05-20. No repo found (gh search returned nothing).
- Idea: complementary-learning-systems framing; a learned consolidator reads memory regions as static input, inspects entries and source trajectories with bounded tool use, and emits compact replacement sets. Trained with GRPO using downstream agent performance as the reward on ScienceWorld. Claims 7 points over baseline with 12x smaller active memory, transfer to ALFWorld and WebArena.
- Plumbline use: the useful part is the shape, not the training: consolidation as a bounded, read-only inspection of source trajectories with a measurable downstream reward. Our reward is replay accuracy against human decisions, computed without learning.
- Limits: needs RL training, replaces memory (destructive), reward is task success in simulated games. Do not adopt the learned consolidator.

### 2.4 TrustMem (PREPRINT)
- Metadata: arXiv 2606.25161 (https://arxiv.org/abs/2606.25161), Yang, Paul, Srinivasan, Kulkarni, Chappidi, 2026-06-23.
- Idea: a Memory Transition Verifier scores every proposed memory update on coverage (nothing important omitted), preservation (existing memory not corrupted) and faithfulness (no unsupported content), then preference-trains the updater. Reported on MemoryAgentBench, HaluMem, Mem-alpha: 40.1 percent fewer omission errors, 79.1 percent fewer corruption errors, 50.0 percent fewer hallucination errors (author-reported).
- Plumbline use: take the verifier, not the trainer. Every sleep or dream write is a `MemoryTransition {before, after}` checked deterministically: coverage = every cited entity and rule id from sources is still reachable; preservation = no source record changed (hash equal); faithfulness = every claim in a derived record has a source id whose text contains the quoted span (our L0 check reused). A transition that fails any check is rejected, never repaired.
- Limits: LLM-based verifier in the paper; ours must be mechanical to keep the "validator rejects, never repairs" rule.

### 2.5 Retain or Consolidate, and The Epistemics of Agent Memory (PREPRINTS)
- Metadata: arXiv 2607.17545 (https://arxiv.org/abs/2607.17545), Kang et al., 2026-07-20: consolidation helps up to 48 percent under tight token budgets, retention is better under loose budgets. arXiv 2609.33013 (https://arxiv.org/abs/2609.33013), Annapureddy and Thamatani, 2026-09-26: introduces ConsolidationBench, reports that quality metrics did not predict real transfer accuracy across 2,532 cases, and describes "governed consolidation" with poison resistance and auditability.
- Plumbline use: consolidation is a budget decision, not a default. Our precedent store is small relative to a modern context window, so the default is retain; dreaming activates only when retrieval cost or conflict density crosses a stated threshold. The second paper's finding that intrinsic quality scores do not predict transfer supports judging consolidation only by held-out replay, never by a model's opinion of the summary.
- Limits: both unreplicated, and the benchmarks they introduce are their own.

### 2.6 Active Dreaming Memory (PREPRINT, not on arXiv)
- Metadata: engrXiv preprint 5919 (https://engrxiv.org/preprint/view/5919), single author, posted 2025-12-03, no peer review indicated. Code claimed, not located.
- Idea: candidate rules are verified by counterfactual simulation on synthetic scenarios before entering long-term memory, to check the rule solves the problem class and not just the triggering instance. Claims 2x first-episode learning, 83 percent success, 95 percent retention after 500 episodes (all author-reported, unreplicated).
- Plumbline use: the right instinct (verify a rule before it is stored) with the wrong instrument (LLM-generated synthetic scenarios can encode the same misconception as the rule). Replace synthetic scenarios with replay over real past cases plus mutation of real cases through the deterministic rule engine (change one field, observe whether the proposal flips only where it should).
- Limits: weakest evidence base in this section; cite for the idea only.

### 2.7 Agentic Context Engineering (ACE)
- Metadata: arXiv 2510.04618 (https://arxiv.org/abs/2510.04618), ICLR 2026 per the abstract page, submitted 2025-10-06, revised 2026-03-29. Repo ace-agent/ace: 1361 stars / Apache-2.0 / 2026-08-24 (repo description matches ACE; that it is the official release is NOT VERIFIED).
- Idea: names two failure modes of LLM-maintained context: brevity bias (concise summaries drop domain insight) and context collapse (iterative rewriting erodes detail). Mitigation: generator, reflector, curator roles with incremental delta updates to a structured playbook instead of whole rewrites. Reports +10.6 percent on agent benchmarks and +8.6 percent on finance tasks (author-reported).
- Plumbline use: validates "never rewrite, only append deltas". Our rule store is already versioned policy-as-code; ACE adds the vocabulary for why an LLM must never regenerate a rule text wholesale. Delta = `RuleProposal.patch` against a named base version, applied only after approval.
- Limits: its playbook is natural-language bullets curated by an LLM, which is the thing we exclude from the decision path.

## 3. Memory systems and their published evaluations (read critically)

### 3.1 mem0 paper: what the evaluation actually shows
- Metadata: arXiv 2504.19413 (https://arxiv.org/abs/2504.19413), Chhikara, Khant, Aryan, Singh, Yadav, 2025-04-28. Repo mem0ai/mem0: 67108 / Apache-2.0 / 2026-10-12.
- Verified from the paper's HTML: only four LoCoMo categories were scored; the adversarial category was excluded "because ground truth answers were unavailable"; the metric is an LLM-as-a-judge score; 10 runs with mean and standard deviation. Its own numbers: full-context about 73 percent J at about 17 s p95 latency, Mem0 66.88 percent J at about 1.44 s (92 percent latency reduction). The headline "26 percent relative improvement" is against OpenAI's memory feature, not against full context; Mem0 scores below full-context on accuracy.
- Dispute: Zep's blog "Lies, Damn Lies, & Statistics" (https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/) argues Mem0 mis-implemented Zep and that a correct run scores about 75 percent. Seen through a search snippet only; the page itself was not fetched. Treat as an unresolved vendor dispute: neither side's number is independently reproduced.
- Plumbline use: report accuracy against full-context AND against a no-memory baseline in every experiment; never compare against a competitor we configured ourselves without publishing the config.

### 3.2 A-MEM
- Metadata: arXiv 2502.12110 (https://arxiv.org/abs/2502.12110), Xu et al., NeurIPS 2025 per the abstract page, v11 2025-10-08. Repos WujiangXu/A-mem 988 / MIT / 2026-03-05 (evaluation code) and agiresearch/A-mem 1199 / MIT / 2025-12-12.
- Verified from the HTML: LoCoMo with F1, BLEU-1, ROUGE-L, ROUGE-2, METEOR, SBERT similarity; the adversarial category is included; no error bars, with the authors citing cost ("Multiple calls will significantly increase costs"). Ablation: without link generation and evolution 9.65 F1 on multi-hop, without evolution 21.35, full 27.02.
- Idea: Zettelkasten notes whose attributes are rewritten when new related notes arrive ("memory evolution").
- Plumbline use: borrow note-level keywords and tags for retrieval, reject evolution. Rewriting an old note when a new one arrives mutates history and removes the ability to answer "what did we believe on date X". Our equivalent is a new `supersedes` record plus a ledger entry (brief A.1 gap 9 already requires setting `supersededBy`).
- Limits: lexical overlap metrics, single-run results, a benchmark with a known flawed key (section 9.1).

### 3.3 Zep and Graphiti
- Metadata: arXiv 2501.13956 (https://arxiv.org/abs/2501.13956), Rasmussen et al., 2025-01-20. Repo getzep/graphiti: 31702 / Apache-2.0 / 2026-10-13. Already torn down in `prior-art/01`.
- Only new point here: the paper's claims are DMR 94.8 percent versus MemGPT 93.4 percent and up to 18.5 percent gain with 90 percent lower latency on LongMemEval (author-reported). LongMemEval-S fits in a single context window for most current models (see 9.2), so a latency or token gain there is not the same as a memory gain.

### 3.4 MemOS, MemoryOS, MIRIX (system papers)
- MemOS: arXiv 2507.03724 (https://arxiv.org/abs/2507.03724), 39 authors, 2025-07-04, revised 2025-12-03. Repo MemTensor/MemOS 11848 / Apache-2.0 / 2026-10-10. Idea: `MemCube`, a unit of memory with provenance and versioning metadata, spanning plaintext, activation and parametric memory. Plumbline takes only the MemCube idea: a record envelope `{content, provenance, version, lifecycle}`, which H-MEM's canonical record already is. Parametric and activation-level memory are rejected (not auditable, not erasable by id).
- MemoryOS: arXiv 2506.06326 (https://arxiv.org/abs/2506.06326), 2025-05-30. Repo BAI-LAB/MemoryOS 1598 / Apache-2.0 / 2026-07-07 (EMNLP 2025 Oral per repo). Short, mid and long-term tiers with FIFO promotion and a "heat" score for mid-to-long promotion. Maps onto H-MEM's three layers; its heat-based promotion has no outcome input. Reported LoCoMo gains (about 49 percent F1) are against weak baselines on a flawed benchmark.
- MIRIX: arXiv 2507.07957 (https://arxiv.org/abs/2507.07957), Wang and Chen, 2025-07-10. Repo Mirix-AI/MIRIX 3451 / Apache-2.0 / 2026-10-08. Six memory types (core, episodic, semantic, procedural, resource, knowledge vault) managed by dedicated agents. Self-reported 85.4 percent on LoCoMo. Plumbline use: the type split matches CoALA and our section 10; its agent-per-memory-type routing adds LLM calls on the write path, which conflicts with our deterministic write path.

### 3.5 HippoRAG 2
- Metadata: arXiv 2502.14802 (https://arxiv.org/abs/2502.14802), Gutierrez et al., ICML 2025 per abstract page. Repo OSU-NLP-Group/HippoRAG: 4059 / MIT / 2026-10-06. Torn down in `prior-art/01`.
- Relevant addition: its Personalized PageRank over a passage-and-entity graph is the best-evidenced route for multi-hop associative recall. For Plumbline's ownership-chain cases the World Model graph plus deterministic traversal already beats PPR on explainability (the path is the explanation). Keep PPR as an optional recall enhancer in the async `queryAsync` path only, never in the sync conformance path. Reported +7 percent on associative tasks is author-reported.

### 3.6 Bitemporal agent memory (2026 PREPRINTS)
- Engram: arXiv 2606.09900 (https://arxiv.org/abs/2606.09900), L. Wang, 2026-06-05. Fast write path appends lossless episodes with no LLM on the critical path; an async process extracts atomic facts, builds a graph and resolves contradictions by invalidate-never-delete; reads combine dense, lexical, graph and recency signals with point-in-time filtering. Reports 83.6 percent on LongMemEval-S with about 9.6k tokens against 73.2 percent for full context at 79k (author-reported; McNemar p below 10^-6 is author-reported; the paper also lists measurement-integrity problems it says it controlled: truncation artefacts, inconsistent judges, full-history leaks). Notably the authors state all questions were used for development.
- Graph-native bitemporal store: arXiv 2607.26520 (https://arxiv.org/abs/2607.26520), Niksarli and Baheti, 2026-07-29. Immutable identity nodes linked to versioned content nodes with valid-time and transaction-time intervals in Neo4j; reports 46.7 percent R@10 overall, 80 percent on knowledge updates, 37.5 percent on temporal reasoning, and names "post-filter dilution" as a failure mode.
- ChronoMem: arXiv 2607.27773 (https://arxiv.org/abs/2607.27773), Su, Xu, Zuo, Bertino, 2026-07-30. Whole-memory snapshot per write plus natural-language rollback requests.
- Plumbline use: independent confirmation that our design (event time vs system time, supersede never delete, fast no-LLM write path, async enrichment) is where 2026 work converged. Two concrete borrowings: (1) the write path appends the raw episode first and enrichment is asynchronous and itself an event; (2) the graph-native paper's post-filter dilution warning: apply `validAt/knownAt` filters inside the candidate query, not after top-k.
- Limits: both single-author or small-team preprints; the point-in-time numbers are low (temporal reasoning 37.5 percent), so bitemporality alone does not solve temporal questions.

### 3.7 Raw versus extracted memory (2026 PREPRINTS)
- TierMem: arXiv 2602.17913 (https://arxiv.org/abs/2602.17913), Zhu, Chen, Yu, Wu, Wang, 2026-02-20. Two tiers; answer from summaries and fall back to raw logs only when summaries prove insufficient; reports 0.851 on LoCoMo with 54.1 percent fewer input tokens and 60.7 percent lower latency than raw-only.
- Jev, a pre-registered test: arXiv 2609.34227 (https://arxiv.org/abs/2609.34227), Sharma and Lall, 2026-09-28. Raw turns were non-inferior to LLM extraction at tight budgets at roughly 3,000x lower cost; reranking benefit shrinks with larger budgets.
- Plumbline use: supports "summary as a view, raw episode as truth". Every derived or summarised record carries `rawRefs[]`, and the decision judge can open the raw episode when a summary lacks the needed evidence. The pre-registration practice is worth copying: freeze the ablation list and metrics in `docs/evaluation/` before running.

## 4. Experience, skills and procedure libraries

### 4.1 ReasoningBank
- Metadata: arXiv 2509.25140 (https://arxiv.org/abs/2509.25140), Ouyang et al., ICLR 2026 per abstract page. Repo google-research/reasoning-bank: 613 / Apache-2.0 / 2026-08-05.
- Idea: store generalisable strategies distilled from BOTH successful and failed experiences, and scale test-time interaction (MaTTS) to produce contrastive signal for better memories. Success and failure labels are self-judged by the agent (abstract: "self-judged successful and failed experiences").
- Plumbline use: the best published argument that failures belong in the store. For us that is the counter-precedent requirement: every retrieval returns supporting and opposing cases. The weakness is also instructive: self-judged labels are a trust hole. Plumbline outcome labels come only from tier T0 (human adjudication) or T1 (system-observed downstream event such as a reversal or a chargeback), never from the deciding model.
- Limits: web and software-engineering tasks, no adversarial setting, outcome labels from an LLM judge.

### 4.2 Memento (case-based reasoning with a learned case selector)
- Metadata: arXiv 2508.16153 (https://arxiv.org/abs/2508.16153), Zhou et al., 2025-08-22. Repo Agent-on-the-Fly/Memento: 2595 / MIT / 2025-10-05.
- Idea: a memory-augmented MDP where episodic cases are retrieved by a learned case-selection policy and the memory is rewritten online; no weight updates. Reports 87.88 percent Pass@3 on GAIA validation and 79.40 percent on test (author-reported).
- Plumbline use: the formal framing (retrieval policy as the learned object, language model frozen) matches precedent memory. We keep the structure and replace the learned neural selector with a fixed, inspectable scoring function plus outcome and rule-version factors (section 10, contribution A). A learned selector could be trained later offline from replay and shipped only as a proposal.
- Limits: GAIA is a tool-use QA benchmark; no decision-precedent semantics; learned selector is not auditable.

### 4.3 Procedure and skill libraries: Voyager, Agent Workflow Memory, Memp, ExpeL
- Voyager: arXiv 2305.16291 (https://arxiv.org/abs/2305.16291), 2023-05-25. Repo MineDojo/Voyager 7259 / MIT / 2024-04-03. Executable skill library, automatic curriculum, self-verification. Skills are code, which is checkable by running it; that is why the library works.
- Agent Workflow Memory: arXiv 2409.07429 (https://arxiv.org/abs/2409.07429), Wang, Mao, Fried, Neubig, 2024-09-11. Repo zorazrw/agent-workflow-memory 478 / Apache-2.0 / 2025-12-22. Induces reusable workflows offline or online; reports 24.6 percent relative gain on Mind2Web and 51.1 percent on WebArena (author-reported), larger gains as train-test distribution gap widens.
- Memp: arXiv 2508.06433 (https://arxiv.org/abs/2508.06433), Fang et al., ACL 2026 Findings per abstract page. Repo zjunlp/MemP 40 / MIT / 2026-01-30. Build, retrieve, update operations over step-level and script-level procedural memory; procedural memory from a stronger model transfers to a weaker one.
- ExpeL: arXiv 2308.10144 (https://arxiv.org/abs/2308.10144), AAAI-24. Repo LeapLabTHU/ExpeL 245 / Apache-2.0 / 2024-12-20. Extracts natural-language insights from trajectories and recalls them with past experiences. How its rule add/edit/remove works was not visible on the abstract page; read the source before copying.
- Plumbline use: our procedural memory is policy-as-code with ids, versions and tests, which is Voyager's "executable and verifiable" property applied to rules. The transferable idea is AWM's separation of induction (offline, from a batch of episodes) from use (online, read-only), and Memp's finding that procedures transfer between models, which suggests rule proposals mined by a strong model remain valid when a cheaper model runs the judge. Proposals are tested by replay, never by the model that wrote them.
- Limits: all four evaluate on web, game or household tasks where success is automatically scored; Plumbline's outcomes are delayed, partial and sometimes never observed.

### 4.4 Hindsight relabelling and replay
- AgentHER: arXiv 2603.21357 (https://arxiv.org/abs/2603.21357), L. Ding, 2026-03-22, v4 2026-05-10. Turns failed trajectories into positive demonstrations for an achievable alternative goal via failure classification, outcome extraction and confidence-gated relabelling; reports +7.6 to 11.4 percent over success-only data on WebArena and ToolBench, with label noise cut by cross-model verification (author-reported). PREPRINT.
- Plumbline use: separate `decision.action` (what we did, immutable) from `outcome.realisedCorrectAction` (what later evidence says was right). A denied release that a later audit shows was safe becomes a labelled positive example for the rule that would have allowed it, without altering the original decision record. This is how dreaming gets training signal from our own mistakes while history stays intact.
- Limits: relabelling in a compliance setting risks encoding hindsight bias; relabels must carry an evidence id and tier T0 or T1.

### 4.5 Reflection pitfalls
- Huang et al., "Large Language Models Cannot Self-Correct Reasoning Yet": arXiv 2310.01798 (https://arxiv.org/abs/2310.01798), 2023-10-03, revised 2024-03-14. Without external feedback, self-correction fails to help and can degrade performance. Reflexion (arXiv 2303.11366, https://arxiv.org/abs/2303.11366, listed by the arXiv API; already torn down in `prior-art/05`) relies on an external success signal for exactly this reason.
- ACE and Useful Memories (2.7, 2.2) add the memory-level analogue: reflection written back into memory compounds error (context collapse, spurious rules).
- Plumbline use: confirms the spec's bounded reflexion (trigger only on a deterministic failure or a human rejection, at most 2 retries). Add one more rule: a reflection is an episode attached to the case, never an edit to a rule or a prior record.

### 4.6 Credit assignment for memory (PREPRINTS)
- Causal Memory Policy: arXiv 2610.02070 (https://arxiv.org/abs/2610.02070), Behnam and Wang, 2026-10-01. Reserves a fixed number of context slots for memories sampled with known propensities and applies inverse-propensity weighting to estimate memory utility despite retrieval selection bias; AUC for separating useful from unnecessary memories rose from 0.54 to 0.66, and the authors conclude identified utility alone is not sufficient for retention decisions.
- MemQ: arXiv 2605.08374 (https://arxiv.org/abs/2605.08374), Liao et al., 2026-05-08. Credit that decays with distance over a provenance DAG.
- Hindsight Memory-PRM: arXiv 2608.29605 (https://arxiv.org/abs/2608.29605), Jia et al., 2026-08-30. Credits memory operations from machine-readable evidence (retrieval hits, answer-time citations).
- Plumbline use: our outcome-to-feedback adapter has a selection-bias problem: precedents that are never retrieved never get outcome feedback. Adopt the CMP idea in SHADOW mode only: on a sampled fraction of cases, log which precedent the judge would have seen under a randomised slot and the resulting rule-engine-consistent action, without letting the shadow retrieval affect the live decision. Propensities are stored on the retrieval trace. Live exploration in a release-approval path is not acceptable.
- The citation-credit idea from Memory-PRM fits our "cite real precedent ids, validator rejects" rule: a precedent that is cited and survives the critic earns feedback `helpful`; one that is retrieved and ignored earns nothing.
- Limits: all three are preprints with unreplicated, small-effect numbers.

## 5. Forgetting and decay

- MemoryBank: arXiv 2305.10250 (https://arxiv.org/abs/2305.10250), Zhong et al., 2023-05-17 (Ebbinghaus-inspired decay). Repo zhongwanjun/MemoryBank-SiliconFriend: 456 / MIT / 2023-05-24. The origin of exponential decay in agent memory and the model for H-MEM's recency term (`exp(-age/14d)`).
- What Eviction Destroys: arXiv 2609.08279 (https://arxiv.org/abs/2609.08279), C. Shen, 2026-09-08 (PREPRINT). A "restore counterfactual" re-inserts gold evidence at read time to split errors into recoverable, irreversible and residual. On LongMemEval-S the irreversible share is 0.60 to 0.73 at an 80k-token budget across FIFO, random, redundancy-aware and LLM-importance eviction, and 1.00 at 8k. In plain terms: eviction policies destroy information that retrieval cannot get back.
- Memora and FAMA: arXiv 2604.20006 (https://arxiv.org/abs/2604.20006), Uddin et al., ACL 2026 Findings per abstract page. A benchmark over weeks-to-months of personal interaction with a metric (Forgetting-Aware Memory Accuracy) that penalises use of outdated information; reports that memory agents frequently reuse invalid memories and improve only marginally over LLMs alone.
- Stale, Misattributed, or Late: arXiv 2610.10265 (https://arxiv.org/abs/2610.10265), Deng and Sinchaisri, 2026-10-07 (PREPRINT). Failure taxonomy before generation; 70.3 percent of prompts exposed a superseded value without update resolution; evaluate validity, identity resolution and latency separately.
- LISTING ONLY (title seen on arXiv listing, abstract not read): FadeMem 2601.18642, SF-AMS 2607.22562, FSFM 2604.20300, "What to Keep, What to Forget" 2607.08032.
- Plumbline use: forgetting means archive with restore, never delete. Decay applies to retrieval weight of generic memory (H-MEM layer and recency terms, as specified), and does NOT apply to precedents: a precedent's relevance is governed by validity (rule version still equivalent? retracted? outcome known?) rather than age. Archive eligibility must require "no unresolved conflict, no dependent decision still under audit" (the guardrails brief A.1 gap 7 says the reference lacks). Every archive action writes a `restoreCounterfactual` test to the eval: restore the item, re-run the affected decisions, and measure whether any decision flips. That makes the cost of forgetting a measured quantity.
- Limits: decay curves are a heuristic with no domain validation; Memora is personal-assistant data, not compliance data.

## 6. Memory poisoning, provenance and trust

### 6.1 Attacks
- MINJA: arXiv 2503.03704 (https://arxiv.org/abs/2503.03704), Dong et al., NeurIPS 2025, revised 2026-02-12. Repo dsh3n77/MINJA: 38 / MIT / 2026-08-11 (README citation matches the paper). Injects malicious records through ordinary queries only, using bridging steps and a progressively shortened indication prompt, so that later victim queries retrieve the poisoned records. Reported over 95 percent injection success and 70 percent attack success under idealised conditions.
- AgentPoison: arXiv 2407.12784 (https://arxiv.org/abs/2407.12784), Chen, Xiang, Xiao, Song, Li, 2024-07-17. Repo AI-secure/AgentPoison 245 / MIT / 2026-10-13. Backdoors memory or a RAG knowledge base with triggered demonstrations; reports over 80 percent attack success at under 0.1 percent poison rate with under 1 percent benign impact. Assumes write access to the memory or knowledge base.
- Reality check: arXiv 2601.05504 (https://arxiv.org/abs/2601.05504), Sunil et al., 2026-01-09 (PREPRINT, healthcare, MIMIC-III): when the store already holds legitimate memories, attack success drops substantially compared with the idealised MINJA setting; their defences (composite trust scoring, temporal decay with pattern filtering) need careful threshold calibration. Karunanidhi, arXiv 2608.21230 (https://arxiv.org/abs/2608.21230), 2026-08-21 (PREPRINT): poisoning 1.2 percent of a corpus cut accuracy from 0.850 to 0.300 in their setting.
- Self-propagating misalignment: arXiv 2610.04083 (https://arxiv.org/abs/2610.04083), 2026-10-02 (PREPRINT): agents themselves wrote misaligned goals into persistent memory in 58 percent of runs when objectives were explicit; when memory tools were disabled, agents wrote goals to files in 74 percent of sessions; a memory auditor cut propagation from 71 to 34 percent only.
- Plumbline relevance: our precedent store is the AgentPoison/MINJA target (retrieved past decisions steer new ones). MINJA needs the victim to write the attacker's reasoning into memory by chat; in Plumbline the write path takes case content from untrusted documents and counterparties, which is a stronger threat than a chat user. The self-propagation result argues that agent-authored memory (reflections, dream outputs) is itself untrusted input to later runs.

### 6.2 Defences with evidence, and defences without
- A-MemGuard: arXiv 2510.02373 (https://arxiv.org/abs/2510.02373), Wei et al., ICML 2026 poster per https://icml.cc/virtual/2026/poster/61006. Repo TangciuYueng/AMemGuard: 17 / MIT / 2026-07-02. Consensus validation compares reasoning paths from several related memories to flag anomalies; a separate lessons store records detected failures and is consulted before action. Claims over 95 percent attack-success reduction with minimal utility cost (author-reported).
- DREAM: arXiv 2610.13267 (https://arxiv.org/abs/2610.13267), Liu et al., 2026-10-09 (PREPRINT): reactivate suspect memories, diagnose by activation pattern, suppress. Claims 2.13x faster and 37.7 percent fewer tokens than A-MemGuard. Compared only against the same family.
- The price of defences: arXiv 2609.22818 (https://arxiv.org/abs/2609.22818), Bhowmik, 2026-09-19 (PREPRINT). Write-time defences (input sanitisation, provenance checking, LLM anomaly detection) had negligible benign-case cost; the read-time reranker lost 4.4 points of accuracy and falsely quarantined legitimate memories in 33.6 percent of cases (up to 106 false quarantines in one conversation).
- Negative results worth heeding: content screening rejected 0 of 360 poisoned memories and additive provenance weighting had negligible effect (p = 0.80), with the dilemma that weights strong enough to block poison also remove legitimate untrusted evidence; the author recommends bounded occupancy at retrieval instead (2608.21230, above). A provenance-based poisoning detector had false-positive rates of 24.7 to 57.6 percent and PPV of at most 3.85 percent at 1 percent prevalence, and its authors withdrew their earlier recommendation (arXiv 2606.30566, https://arxiv.org/abs/2606.30566, Leong, PREPRINT).
- Structural defences with the strongest argument:
  - Memory Provenance Laundering: arXiv 2607.29167 (https://arxiv.org/abs/2607.29167), Xu et al., 2026-07-31 (PREPRINT). External observations get rewritten as apparent user history during consolidation, hiding origin; vulnerable consolidated memories showed 100 percent attack success; a Provenance-Preserving Memory Firewall that authorises actions by matching risk to provenance authority blocked all unauthorised high-risk actions in their tests.
  - PACMI: arXiv 2610.05732 (https://arxiv.org/abs/2610.05732), Wang et al., 2026-10-05 (PREPRINT). Provenance graph with typed dependency edges and a four-state validity system, cascading invalidation to dependents; on a 100-case benchmark final-answer errors fell from 11 to 3.
  - Dependency-guided rollback: arXiv 2608.10502 (https://arxiv.org/abs/2608.10502), Yu et al., 2026-08-11 (PREPRINT). Typed memory-to-action graph from runtime provenance, selective repair instead of delete-all; 85.3 percent versus 77.3 percent recovery on 150 cases, 68.0 versus 54.0 percent on a 50-case stress set.
  - MemIR: arXiv 2605.25869 (https://arxiv.org/abs/2605.25869), Jin et al., 2026-05-25 (PREPRINT). Typed "grounded atoms" separating raw evidence, retrieval cues and truth-bearing claims to prevent provenance-role collapse (source-monitoring errors).
  - Nous: arXiv 2606.22030 (https://arxiv.org/abs/2606.22030), P. Singh, 2026-06-20 (PREPRINT). Belief tracking per entity-attribute with reliability-conditioned updating; belief updating beat last-write-wins when sources differ in trustworthiness; a provenance cap bounds poison influence.
  - MemGuard (agent-memory sense): arXiv 2608.21867 (https://arxiv.org/abs/2608.21867), Wang et al., 2026-08-22 (PREPRINT). Persists verifier signals (reward, confidence, label, uncertainty) as metadata through retrieval, conflict resolution, summarisation and archival. Name clash warning: arXiv 2609.04547 "MemGuard" is a hardware memory-bandwidth paper and unrelated.
  - PACE: arXiv 2610.01349 (https://arxiv.org/abs/2610.01349), Li et al., 2026-10-01 (PREPRINT, security). Provenance-aware capability enforcement before each tool call; effect verification accounted for most gains. The same mediator pattern is what Scout Intent's signed execution contracts do.
- Plumbline use, as a single write-path and read-path design (all four required by spec section 10 already; the literature supplies the failure data):
  1. Tier algebra with non-amplification: `tier(derived) = min(tier(inputs))`. A consolidation, dream or reflection can never raise trust above its weakest input and records its `derivedFrom` ids. This directly blocks provenance laundering.
  2. Typed memory atoms (MemIR): `RawEvidence` (hash-pinned document span), `Cue` (index terms, never shown as truth), `Claim` (subject, attribute, value, evidence ids, tier). Only claims reach the judge.
  3. Bounded occupancy at retrieval instead of additive penalties: of the top N shown to the judge, at most `k_T3` may come from tier T3 or one origin, and T3 records carry an explicit "untrusted" label. Autonomy above L1 requires at least one T0 or T1 precedent in the supporting set.
  4. Dependency graph from the start: every decision record stores `{precedentIds, factIds, ruleVersion, evidenceHashes}`; retraction of any memory computes the blast radius exactly (section 10, contribution C).
  5. Defences stay in write-time, structural form (provenance stamp, schema, dedupe, contradiction check, approval for T3 writes). No LLM content filter is relied on; the data above shows content screening missing poison entirely.
- Limits: nearly all defence numbers are author-reported on author-built attacks; there is no standard adaptive-attack benchmark for precedent stores. We must build one (section 10, item 4 of benchmarks).

## 7. Cognitive-science foundations

- Complementary learning systems: McClelland, McNaughton, O'Reilly, "Why there are complementary learning systems in the hippocampus and neocortex", Psychological Review, 1995 (indexed in Europe PMC, PMID 7624455; abstract confirmed through the Europe PMC REST record; the PubMed page itself would not load without cookies). Argument: a fast system learns individual episodes without disrupting structured knowledge; a slow system integrates gradually through repeated reinstatement.
- Reconsolidation: Nader, Schafe, Le Doux, "Fear memories require protein synthesis in the amygdala for reconsolidation after retrieval", Nature, 2000 (Europe PMC: PMID 10963596, DOI 10.1038/35021052). Retrieved memories become labile and are re-stored. NOTE: an earlier guess at this PMID pointed to an unrelated paper; the value above comes from a title search, not memory.
- LLM-agent readings, all 2026 PREPRINTS: Auto-Dreamer (2.3) and Hippocam, "Use and Disuse" (arXiv 2610.12124, https://arxiv.org/abs/2610.12124, 2026-10-08: nested-intent hierarchy, unused experiences become abstract but originals remain recoverable) lean on CLS. REALM (arXiv 2609.16053, https://arxiv.org/abs/2609.16053, 2026-09-13) reorganises memory from retrieval feedback in the name of reconsolidation, reporting 75.97 percent on LoCoMo and 65.11 percent on LongMemEval, both on benchmarks with the problems in section 9.
- Plumbline use, and a caution. CLS gives a principled split: fast episodic store (H-MEM `short_term` to `working`, append-only) and slow structured store (versioned rules, reached only through approval). The cognitive-science result that matters most for design is the one the agent literature keeps ignoring: in the brain, slow integration uses interleaved replay of many episodes, which is our replay-validation requirement. Reconsolidation is the risky half: it is the biological case for editing a memory on retrieval, and 2.2 and 2.7 show LLM implementations of it degrade memory. We use reconsolidation only as an argument for appending a retrieval-time annotation (`reinforced`, `contradicted-by`) to a record, never for rewriting its content.
- Limits: analogy, not evidence; no neuroscience result transfers to an LLM store automatically.

## 8. Markovian and bounded-state reasoning

- The Markovian Thinker (Delethink): arXiv 2510.06557 (https://arxiv.org/abs/2510.06557), Aghajohari et al., 2025-10-08, final revision 2025-11-13. Repo McGill-NLP/the-markovian-thinker: 351 / Apache-2.0 / 2026-03-16. Reasoning in fixed-size chunks (8K) with constant-size state; verified from the HTML: at each boundary the next chunk starts from the query plus the LAST m tokens of the previous chunk's text (m = C/2 by default, so about 4K of 8K), trained with RL on about 40K competition-maths problems (more difficult OpenMath problems for the 96K scaling runs). Reported (abstract): an R1-Distill 1.5B model matches or beats LongCoT-RL trained at a 24K budget; at 96K average thinking length about 27 H100-months versus 7. The paper's own stress test (CrossWordBench) shows degraded results for tasks whose required state exceeds m.
- MEM1: arXiv 2506.15841 (https://arxiv.org/abs/2506.15841), Zhou et al., 2025-06-18. Repo MIT-MI/MEM1 344 / MIT / 2026-01-03. RL-trained agent keeps one compact internal state that jointly does memory consolidation and reasoning; reports 3.5x performance and 3.7x lower memory against Qwen2.5-14B-Instruct on a 16-objective multi-hop QA task (author-reported).
- MemAgent: arXiv 2507.02259 (https://arxiv.org/abs/2507.02259), Yu et al., 2025-07-03, revised 2026-07-29. Repo BytedTsinghua-SIA/MemAgent 1111 / Apache-2.0 / 2026-05-12. Reads text in segments and overwrites a memory with RL; trained at 32K, extrapolates to 3.5M tokens with minimal degradation and 95 percent plus on 512K RULER (author-reported).
- Plumbline use. All three carry free text (or latent state) across chunks; Plumbline's carryover carries ids. Concretely:
  ```ts
  interface Carryover {
    goalHash: Hash; asOf: { worldModelSeq: number; ruleVersion: string };
    resolvedFactIds: Id[]; openQuestions: { id: Id; about: Id; why: string }[];
    claimsSoFar: { claimId: Id; evidenceIds: Id[]; tier: TrustTier }[];
    freeNote: string; // hard cap, e.g. 200 tokens, advisory only
  }
  ```
  A chunk may use a fact only if its id resolves in the World Model at `asOf`; the carryover validator re-resolves every id and compares hashes before the next chunk starts, so a crash, a restart or a changed rule version cannot silently change meaning. Failure mode this removes: Delethink's tail text can carry a hallucinated "fact" forward with no source; ours cannot, since only ids that resolve are legal. Failure mode this adds: state that is not expressible as ids (a hypothesis, an arithmetic partial) has no home, which is exactly the capacity limit CrossWordBench exposed; `openQuestions` and the capped `freeNote` are the pressure valve and their overflow must raise `carryover-overflow`, not truncate.
- Tradeoffs to state plainly: the break-even `N > 1 + 2C/O` from the Meterless model means short cases gain nothing; measured (provider-reported) prompt tokens must replace `ceil(chars/4)` before any efficiency claim; the Delethink result is about trained models on maths and does not transfer as evidence for untrained prompt-level chunking on investigation tasks. Our evaluation: for deep ownership chains of depth 3 to 12, compare one-shot context against Markovian chunks on answer equality, cited-evidence validity, and tokens, three runs each, report the worst.
- Limits: all three need or assume trained models; our prompt-level variant is the engine spec's, not these papers'.

## 9. Memory benchmarks and their known flaws

### 9.1 LoCoMo (use only as a sanity check)
- Metadata: arXiv 2402.17753 (https://arxiv.org/abs/2402.17753), 2024-02-27. Repo snap-research/locomo: 1223 / NOASSERTION licence / 2024-08-13 (no licence assertion: check before vendoring).
- Third-party audit (Penfield Labs, 2026-04-08, https://penfieldlabs.substack.com/p/we-audited-locomo-64-of-the-answer; repo dial481/locomo-audit 21 / NOASSERTION / 2026-04-02): reports 99 score-corrupting errors in 1,540 questions (6.4 percent), including answer-key facts not present in the conversation, wrong temporal arithmetic, and 24 questions attributing statements to the wrong speaker; a ceiling of about 93.6 percent for a perfect system; and a gpt-4o-mini judge that accepted 62.81 percent of deliberately wrong but topically adjacent answers while catching specific wrong names or dates about 89 percent of the time. NOT independently reproduced by us; the audit is a single third-party report.
- Other facts: Mem0 excluded the adversarial category (3.1); Letta reported 74.0 percent on LoCoMo by storing conversations in files that an agent searches with grep, against Mem0's reported 68.5 percent (https://www.letta.com/blog/benchmarking-ai-agent-memory, 2025-08-12; the authors themselves say memory benchmarks of this type may not be very meaningful and that the setup needed tool rules). Together these say: a filesystem and a capable agent match specialised memory on LoCoMo.

### 9.2 LongMemEval
- Metadata: arXiv 2410.10813 (https://arxiv.org/abs/2410.10813), Wu et al., ICLR 2025. Repo xiaowu0162/LongMemEval: 1148 / MIT / 2026-05-11. 500 questions over five abilities: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention. Reported 30 percent accuracy drop for commercial assistants and long-context models on sustained interactions.
- Critiques: the Penfield audit states LongMemEval-S is "a context window test rather than a memory test" because about 115K tokens per question fit most current windows; Engram (3.6) and the audit paper below both note judge and leakage problems; arXiv 2609.38021 (https://arxiv.org/abs/2609.38021), Chanhnourack, 2026-09-29 (PREPRINT): on 500 LongMemEval-S questions, reader scores vary widely on fixed packets, re-judging identical answers changed only three labels, a negative control rejected a verifier that repaired three wrong drafts and broke eleven correct ones, and all questions had been used to develop the components with no untouched holdout.
- Use: only the knowledge-update, temporal-reasoning and abstention slices, with a no-memory baseline and a full-context baseline, three runs each, a frozen holdout. The larger "M" variant is mentioned in the benchmark's materials but its size and availability were NOT VERIFIED.

### 9.3 MemoryAgentBench
- Metadata: arXiv 2507.05257 (https://arxiv.org/abs/2507.05257), Hu, Wang, McAuley, ICLR 2026 per the repo description; latest version 2026-06-28. Repo HUST-AI-HYZ/MemoryAgentBench: 467 / MIT / 2026-09-25. Four competencies: accurate retrieval, test-time learning, long-range understanding, selective forgetting; converts existing datasets to incremental multi-turn form; finds current methods fall short on all four.
- Why it fits best: "selective forgetting" and "test-time learning" correspond to our supersession and precedent-learning behaviours, and it stresses incremental ingestion, which matches an event-sourced write path. Caveat: it repackages existing datasets, so it inherits their flaws; check each sub-dataset's key before trusting a score.

### 9.4 2025 to 2026 successors (use as design references or targeted checks)
- HaluMem: arXiv 2511.03506 (https://arxiv.org/abs/2511.03506), Chen et al., 2025-11-05, revised 2026-01-05. Repo MemTensor/HaluMem 175 / NOASSERTION / 2026-09-03. Operation-level evaluation of extraction, update and question answering over about 15k memory points and 3.5k questions with contexts beyond 1M tokens; finds hallucinations arise and accumulate at extraction and update, then propagate to answers. Best match to our "memory write path" acceptance tests, because it scores the write, not just the final answer. Same group as MemOS (vendor-affiliated benchmark: caution).

## 10. Synthesis for Plumbline

### 10.1 Ranked top 10 ideas (best first; rank is by expected effect on defensibility times strength of evidence)
1. **Raw episodes are immutable; consolidation emits only separately stored, replay-validated proposals.** Evidence: 2.2 (utility degrades below no-memory), 2.5, 2.7, 3.7. Write path: `Episode` append-only; `RuleProposal`/`SummaryView` carry `derivedFrom[]` and can be deleted without losing history; sleep never deletes sources (fixes brief A.1 gap 7).
2. **Tier algebra with non-amplification plus typed atoms.** `tier(derived) = min(inputs)`; evidence, cue and claim are different types. Evidence: 6.2 (provenance laundering 100 percent attack success; typed atoms; belief cap).
3. **Decision-dependency graph with exact cascading retraction.** Every decision stores the ids it used; retraction recomputes affected decisions by deterministic re-run. Evidence: PACMI, rollback repair, MemQ; our determinism makes it exact rather than estimated.
4. **Outcome-weighted, rule-version-aware precedent retrieval with mandatory counter-precedents.** Evidence: ReasoningBank (failures belong in memory), Memento (retrieval policy is the learned object), Memora (outdated reuse is common). Detailed in contribution A.
5. **Bitemporal facts with as-of replay and in-query temporal filtering.** Evidence: Engram, graph-native store, Zep; avoid post-filter dilution.
6. **Operation-level evaluation with negative controls and restore counterfactuals.** Evidence: HaluMem, EvalMem, What Eviction Destroys, Auditing LTM evaluation. Score the write, the update and the read separately.
7. **Bounded occupancy at retrieval instead of additive trust penalties; autonomy above L1 needs a T0 or T1 precedent.** Evidence: Utility Under Attack (additive weights ineffective), Price of Safety (read-time reranker costly).
8. **Ids-not-facts Markovian carryover with a validator and `carryover-overflow`.** Evidence: Delethink state limits (CrossWordBench), MEM1/MemAgent show bounded state works when trained; ours differs by construction and must be measured.
9. **Sleep-time precompute as a keyed cache of derived, re-verified artefacts.** Evidence: sleep-time compute (gain tracks query predictability); safe because the cache never holds a decision.
10. **Hindsight outcome relabelling kept separate from the decision record, plus shadow-mode propensity logging for unbiased precedent utility.** Evidence: AgentHER, Causal Memory Policy. Both are low-risk because they only add fields and logs.

### 10.2 Ideas we should NOT adopt, with reasons
- **Online LLM rewriting of memory or notes (A-MEM evolution, ACE-style full rewrites, Letta in-place block edits, Mem0-style LLM-chosen update or delete in the write path; see `prior-art/05` for the Mem0 and A-MEM code review).** Evidence of harm: 2.2, 2.7. Violates append-only and as-of queries.
- **Learned or RL-trained memory managers in the decision path (Auto-Dreamer, TrustMem trainer, MemHarness 2607.28272, Memory-PRM, Memento's neural case selector, MEM1, MemAgent).** Not deterministic, not auditable, need GPUs and reward engineering, and their gains are author-reported on game or QA tasks. Reuse their verifier and reward ideas offline only.
- **Content-filter and consensus defences as the primary poisoning defence (A-MemGuard consensus, DREAM, LLM anomaly filters).** Probabilistic, author-reported, and the negative results in 6.2 show content screening missing every poisoned item and standalone provenance-anomaly detection unusable at realistic prevalence. Keep as optional extra signals, never gates.
- **Additive provenance weights in ranking.** Shown ineffective, and they hide legitimate low-tier evidence.
- **Time decay on precedents (MemoryBank-style).** Relevance depends on rule-version equivalence and outcome, not age; decay would silently retire valid old precedents and keep young invalid ones.
- **Self-judged outcome labels (ReasoningBank).** The deciding model must never be the source of the label that later trains it.
- **Parametric and activation memory (MemOS KV and adapter tiers), latent memory.** Cannot be erased by id, cannot cite evidence.
- **Agent-per-memory-type routing on the write path (MIRIX).** Adds model calls and nondeterminism where the spec requires a deterministic validated write.
- **Headline claims on LoCoMo, or on LongMemEval-S as a memory test.** See 9.1 and 9.2.
- **Synthetic-scenario rule verification (ADM) as the only gate.** The generator can share the rule's misconception.
- **Intrinsic quality scoring of summaries by an LLM.** 2609.33013 reports such scores did not predict transfer.

### 10.3 Three novel research contributions a grant reviewer would value
Novelty statement: we searched arXiv title listings for "precedent memory", "case-based reasoning agents", "memory rollback", "memory provenance", "memory consolidation" and "experience replay LLM agents" and found nothing combining the elements below. That is an absence of evidence from a limited search (no web search was available late in the session), not proof of priority; claims must be softened to "to our knowledge" and re-checked before submission.

**A. Outcome-weighted, rule-version-aware precedent memory with mandatory counter-precedents.**
- Problem: precedent stores in the literature (ReasoningBank, Memento, HiRes at arXiv 2605.21420, a chemistry k-NN precedent memory) retrieve by similarity and, at best, success; none of those we found conditions validity on the policy version that produced the decision, which is the central failure of precedent in governed settings (the rule changed, the precedent stayed).
- Design:
  ```ts
  interface PrecedentRecord {
    id: Id; caseSnapshotHash: Hash; ruleVersion: string; firedRuleIds: Id[];
    action: Action; autonomy: 0|1|2|3;
    outcome: { state: "unknown"|"confirmed"|"reversed"|"incident"; tier: "T0"|"T1"; evidenceIds: Id[]; at: ISO };
    realisedCorrectAction?: Action;            // hindsight field, never overwrites action
    validity: "valid"|"stale_rule_diff"|"retracted"; // recomputed, never stored as truth
    bitemporal: { validFrom: ISO; validTo?: ISO; recordedAt: ISO; supersededAt?: ISO };
  }
  ```
  Validity is computed: re-run the CURRENT deterministic rule engine on the stored `caseSnapshot`; if allowed actions or fired rules differ from those recorded, mark `stale_rule_diff` and attach the rule diff. Score = `hmemScore * outcomeFactor * versionFactor`, with `outcomeFactor` and `versionFactor` from a fixed published table (no learning), applied in the Plumbline retrieval wrapper while the conformance-facing H-MEM keeps its spec formula; outcomes feed H-MEM `feedback()` (confirmed_correct to helpful, reversed or incident to wrong) through an adapter so the ledger records every change. Retrieval runs twice: supporting set, then a counter query constrained to opposite action or reversed outcome under the same similarity gate; if a counter-precedent exists at least one is returned with a per-term explanation. The judge must cite or explicitly dismiss it; the validator rejects a judgement that ignores a returned counter-precedent.
- Evidence to produce: ablation ladder from the spec (rules only, plus precedent, plus recency, plus outcome, plus version-awareness, plus counter-precedent) on a labelled decision set containing planted rule changes; metric = decision accuracy on cases where the rule changed after the precedent, and rate of stale-precedent-driven errors.
- Risks: outcome labels are sparse and delayed; counter-precedent queries can inflate cost; fixed weights are hand-set and need sensitivity analysis.

**B. Consolidation that can only emit replay-validated rule proposals (a typed consolidation interface).**
- Problem: 2.2 shows LLM consolidation can end below no-memory; 2.6 verifies rules with synthetic LLM scenarios; 2.3 learns consolidation by RL and replaces memory.
- Design: the dreaming module's only output type is `RuleProposal`. A proposal is admissible to the approval queue only with a machine-checkable certificate:
  ```ts
  interface Certificate {
    baseRuleVersion: string; patch: RulePatch; supportEpisodeIds: Id[]; counterExampleIds: Id[];
    replay: { split: "temporal-holdout"; n: number; precision: number; recall: number;
              wilsonLower: number; perRuleVersion: Record<string, {n:number;precision:number;recall:number}> };
    mutationTests: { field: string; flipped: boolean; expectedFlip: boolean }[];
    nonAmplification: { inputsMinTier: TrustTier; proposalTier: TrustTier };
    noMutation: { episodeHashesBefore: Hash; episodeHashesAfter: Hash }; // must be equal
  }
  ```
  The queue rejects, never repairs, any proposal whose certificate fails: replay on a temporal holdout (train on earlier episodes, test on later) below the stated Wilson bound, any holdout case where the proposal contradicts a T0 human decision without a listed justification, proposal tier above its inputs' minimum, or any source hash changed. Mutation tests alter one field of real cases and require the proposal to flip exactly where the rule text says it should. The model proposes; deterministic code certifies; a human approves.
- Evidence to produce: the "consolidation-harm curve" (decision accuracy versus number of dream cycles) for (i) unconstrained LLM consolidation that rewrites a summary store, (ii) our proposal-only pipeline. Prediction from 2.2: (i) rises then falls; test that (ii) does not fall. This turns a reported failure mode into a controlled experiment in a new domain.
- Risks: certificates need enough labelled history to have power; the model may propose only rules that are easy to certify; held-out replay can leak if episodes are near-duplicates (dedupe by case fingerprint before the split).

**C. Exact blast-radius retraction over a decision-dependency graph.**
- Problem: PACMI and dependency-guided rollback estimate downstream effect of a bad memory with heuristics or LLM judgement and report moderate recovery (68 to 85 percent in their benchmarks). They cannot be exact because the agent's decisions are not reproducible.
- Design: Plumbline decisions are deterministic functions of `(ruleVersion, World Model facts as of seq, precedent ids retrieved, judge input hash)` up to the bounded model judgement. Store that tuple. On retracting a fact, a precedent or a rule version, (1) mark dependents via the graph, (2) re-run the deterministic stage for each affected decision, (3) report which decisions change allowed-action set (exact), which only change the judgement input (re-judge queue), and which are unaffected. Output is an auditor-facing "if this memory had not existed" report. Poison removal, rule rollback and a bad-source discovery share one mechanism.
- Evidence to produce: plant poison via a MINJA-style write and an AgentPoison-style trigger document into the real pipeline; measure attack success, then time and precision of the blast-radius report versus ground truth by re-running the full history; report recovery exactness (affected-set equality), not an F1.
- Risks: the judgement step is not deterministic, so exactness holds for the policy stage and bounded-state stage only; graph size grows with decisions; needs the "every query mutates state" gap (brief A.1 gap 5) fixed so retrieval reads are side-effect free.

Supporting contribution (smaller): **D.** the ids-not-facts Markovian carryover with a validator (section 8), evaluated for exact crash-restart equivalence and chain-depth scaling with measured tokens, including the cases where chunking loses to one shot.

### 10.4 Memory benchmarks: adopt, adapt, and avoid
- **Adopt as public checks (report next to our own):** MemoryAgentBench (selective forgetting and test-time learning competencies, after checking each sub-dataset's answer key); HaluMem (operation-level write and update scoring; verify its NOASSERTION licence before vendoring); LongMemEval restricted to knowledge-update, temporal and abstention slices with no-memory and full-context baselines and a frozen holdout; BEAM for scale behaviour of the async retrieval path only.
- **Adopt as method, not as dataset:** EvalMem's per-stage defect codes; Auditing-LTM-Evaluation's repeated judging, reader variation and negative controls; What Eviction Destroys' restore counterfactual; Memora's forgetting-aware metric idea (penalise use of outdated information); AMA-Bench's trajectory-memory framing for tool outputs; the pre-registration practice of Jev.
- **Must build ourselves (nothing public measures it):** a precedent benchmark with planted rule changes, reversed outcomes and counter-precedents; a poisoning suite through the real write path (MINJA and AgentPoison adapted, including documents that carry instructions, and agent-authored memory per 2610.04083); the consolidation-harm curve; a carryover crash-restart equivalence test; a planted-conflict gold set (already in spec section 12).
- **Unfit:** LoCoMo as a headline metric (6.4 percent of the key reported wrong by one audit, a judge that accepted 62.81 percent of wrong adjacent answers, and a filesystem agent matching specialised systems on it), DMR (introduced for MemGPT; not examined here, and Zep reports it itself), LongMemEval-S as evidence of memory rather than long-context (about 115K tokens per question), any benchmark scored only by an unvalidated LLM judge, ScreenshotVQA (multimodal, irrelevant), and any number we did not run ourselves with the configuration published.
- Reporting rule for every number in README, deck and video: baseline of no memory and baseline of full context, three runs with the worst shown, judge variance floor, which questions were used for development, and the configuration of any competitor we ran.
